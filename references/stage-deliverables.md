# 三阶段最小产物

以下为**虚构产品 Feedback Flow 的写法示例，不代表任何真实用户已确认**。这些是 Markdown 制作记录，不是强制机器 schema；按项目规模保持简短。流程见 [pipeline.md](pipeline.md)。

## 第一阶段：三图与方向记录

`records/brief.md` 保存受众、真实任务、必展示项、CTA、品牌要求、素材路径和来源。三个候选都展示同一件事，例如“把零散客户反馈整理成优先级清单”。

正式设计前按 [产品研究](product-research.md) 添加简短依据表：“内容/用途 → 来源与观察性质 → 可拍素材/状态 → 缺口”。例如候选“合并反馈”须指向实际页面或材料，注明看见的是功能说明、演示还是实际交互；没有素材时记录缺口，不补造来源。研究较长再拆 `records/research.md`，不强制新文件。

| 候选 | 图片 | 可区分的设计选择 |
| --- | --- | --- |
| A 编辑排版 | `assets/directions/a.png` | 浅底、大字与清楚网格，强调反馈内容 |
| B 精密工作台 | `assets/directions/b.png` | 深底、紧凑层级与单一强调色，聚焦选中项 |
| C 柔和空间 | `assets/directions/c.png` | 有空间层次的卡片、暖色材质，聚焦整理后的秩序 |

名称仅为例子，不要求每次都用这三种风格。每个方向附一句取舍和素材可行性；效果图阶段不制作三条影片。

`records/direction.md` 示例：

```markdown
# Direction v1
候选：A / B / C（图片路径及一句差异）
推荐：B；理由：关键选中态最清楚。
当前选择：待选
确认依据：无；等待用户选择或授权代选。
素材风险：结果页只有低清截图，第三步需补采。
```

有真实选择时才更新为 `选择：B；依据：用户「选 B」；适用版本：direction v1`。明确委托时写 `Agent 代选 B；依据：用户「方向和脚本你决定，直接做完」`。推荐、沉默和模拟批准都不是用户亲选，不编造时间戳。

## 第二阶段：脚本与粗分镜

`records/script.md` 示例：

```markdown
# Script v2
状态：待确认；方向：B / direction v1（仅示例）。
开头：零散反馈，先抓重点。
问题：同类诉求散落在多条反馈中，难以决定先做哪项。
产品介入：选中同类条目，合并，再由用户调整优先级。
结果：同一组反馈变成排好序的清单；用真实界面证明。
结尾：Feedback Flow；查看产品演示。
必展示：选择、合并、排序；不宣称自动 AI 分析或节省百分比。
确认依据：尚无；本版只确认内容、顺序与必展示项。
```

`records/storyboard.md` 的第二阶段形态：

上面的案例式脚本只是示例。功能巡礼可以直接按“搜索→总结→分享”写段落，单功能或成果展示也可以；内容与重点词在本步确认，具体文字方法与时序留到第三步。

| 段落 ID | 内容目的 | 简图 / 画面说明 | 大致时长 |
| --- | --- | --- | --- |
| S01 | 点出问题 | 独立文字：“零散反馈，先抓重点”，关键词留出强调位置 | 约 3 秒 |
| S02 | 看见产品介入 | 框图标记列表、选中条目、合并后条目；同一反馈案例 | 约 8 秒 |
| S03 | 证明结果 | 简图表示用户排序后得到优先级清单 | 约 8 秒 |
| S04 | 记住产品与行动 | 产品名、一个 CTA | 约 4 秒 |

粗略时长用于检查故事规模，允许调整。图可以低保真，不要求最终布局、动效、接缝、帧区间或音乐卡点。用户认可 script v2 后才写入确认原话；如明确委托代定，记录授权与 Agent 决定。不能通过填模板创造批准。

## 第三阶段：在同一分镜补制作信息

保留段落 ID 与内容目的，增加制作列，不覆盖 `script.md` 主线。下面仅展示 S02 的制作层，不是第二步必填项：

| 段落 ID | 焦点 / 主体变化 | 前后承接 | 时间与素材 | 声音 / 检查 |
| --- | --- | --- | --- | --- |
| S02 | 反馈 17/23 被选中→用户合并→保留可辨认文本的新条目 | S01 文案落定后进入列表；合并结果成为 S03 排序对象 | 按实际工程填写半开帧区间 `[start,end)` 与素材路径，此处不预填 | 按下/合并落点对应反馈，结果可读；E01/E02/E03 |

修改记录例：`8.2–9.1s / 合并后直接切页，无法追踪来源 / E02 / 保留同一条目的文字与标色，移动进入清单 / 复看本段及前后接缝，正常速度能跟踪对象`。

需要细化节奏的段落追加一句制作说明即可：`S02 / 节奏：选中短促、结果展开舒展；落点：合并完成；阅读：新条目清晰后留出理解时间；承接：同一条目进入排序。` 文字段落可写 `S01 / 分组“零散反馈 / 先抓重点”，强调“重点”，落定可读后进入列表；参考 T01，具体时长按播放校准。` 方法选择见 [动态表达](motion-language.md)，不要求每镜固定套同一时长或动作。

`选择 B 已确认 / script v2 待确认` 表示停在第二阶段；`direction v1 与 script v2 已确认 / 仅修按钮` 表示留在第三阶段；`初稿存在 / 确认依据缺失 / 本次只授权修按钮` 表示局部修订不扩大为整片批准。

## 接入现有审阅

初始化工具生成 `brief.md`、`direction.md`、`storyboard.md`；第二步按需创建 `script.md`。默认审阅读取前三个记录；脚本通过已有 `reference` role 加到 `records/review-context.json`：

```json
{
  "documents": [{"role": "reference", "path": "records/script.md"}],
  "actionRanges": []
}
```

这是新配置的最小示例。已有配置时将 script 条目合并到 `documents`，保留现有条目与 `actionRanges`，不要用空数组覆盖它们。只有 script 文件实际存在才添加；路径必须在影片工程内。未重命名的 brief/direction/storyboard 仍会默认收集。

研究较多且实际创建了 `records/research.md` 时，同样合并 `{"role":"reference","path":"records/research.md"}`；brief 中的短研究不需要额外配置。动态决定已在 storyboard 中，默认会收集。关键文字替换或交接窗口按实际全局半开帧区间补入 `actionRanges`，保留旧区间，控制采样量；不要用“已确认”模板补造老工程历史。

老工程没有 script 时继续使用真实 brief/storyboard，不补造“已确认脚本”。下一次确实确认新故事时再记录。若重命名记录，用对应 role 指向真实路径；完整接口见 [tech.md](tech.md#使用现有评测工具)。
