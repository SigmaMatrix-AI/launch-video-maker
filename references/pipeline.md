# 制作流程

从产品事实出发，把真实素材、参考镜头和制作规格变成可验证的影片。方向性问题尽量在全片实现前发现；逐镜头检查贯穿制作，独立审查负责最终收口。

全程采用自主决策。以下“进入下一步的条件”是 Agent 的内部检查，不是用户确认关卡。对可推断的缺省项作判断并记录；只有无法合理推断、且确实影响制作的必要信息才提问。已有明确要求持续有效。

阶段条件按相关镜头的依赖判断：已具备内容依据、方向验证和素材的镜头可先实现，其他镜头可继续研究或预排，但分别记录“已验证/待补/受阻”。只有本片所有必需镜头满足条件，才把该阶段整体标记完成；一个局部缺口不阻塞无关工作，也不随其他镜头完成而自动消失。

## 阶段与记录

| 阶段 | 核心判断 | 工作记录 |
| --- | --- | --- |
| 1. 产品理解与执行约束 | 产品解决什么问题，有什么可展示证据，本片要让谁理解什么 | 产品 brief、执行决策、首批真实素材与缺口 |
| 2. 参考拆解与视觉方向 | 借用哪些镜头关系，如何融合 style，真实素材能否承载 | 参考拆解、方向、关键画面与短动态 |
| 3. 功能映射与分镜 | 必须展示的内容是否覆盖，信息与动作能否在时长内成立 | 功能到镜头映射、帧级分镜、声音方向 |
| 4. 按分镜补采素材 | 画面状态、尺寸、分层及清晰度是否满足具体镜头 | 最终使用素材、采集记录、坐标与源片段信息 |
| 5. 逐镜头实现 | 参考动作是否落实，当前帧和连续播放是否可靠 | React 场景、统一时间线、逐镜检查证据 |
| 6. 声音编排 | 声部是否服务画面，时序变化是否同步反映 | 音频时间线、混音及同步记录；或明确静音 |
| 7. 审查与修复 | 产品表达与实际视听质量是否达到约定标准 | 独立报告、问题闭环、明确范围与版本 |
| 8. 按需预览与导出 | 用户请求的是预览还是成片，实际交付物是否验过 | 预览工程；按需生成 MP4 及成片报告 |

每支影片默认创建在本仓库 `films/<project-id>/`，整个 `films/` 由 Git 忽略。用户指定其他位置时遵从；不在 `templates/` 内修改用户影片，不隐式引用其他制片工程的素材。

```text
<film-project>/
  film.tsx                 runtime 入口、配置和场景组合
  src/                     按需拆分场景与共享实现
  records/
    brief.md               产品事实、影片任务、执行约束、证据与缺口
    direction.md           模板/style 选择、参考拆解、视觉决策
    storyboard.md          功能映射、帧区间、动作、文案、素材、声音锚点
    review-context.json    可选：自定义评测文档与动作采样区间
  brand-kit/               Logo、主题色及简短来源；已有明确规范按需保留
  assets/                  截图、录屏、案例及按需使用的音频
    sources.md             来源、页面状态、使用依据与本地文件索引
  .lvm/                    准备缓存、检查画面与版本化 review 证据
  exports/                 用户触发导出后才产生的成片
```

`records/{brief,direction,storyboard}.md` 与 runtime 默认收集位置一致。记录可以合并或改名，但必须通过 `review-context.json` 显式交给评测包，不能只存在聊天中。表格用于保持可追溯，不要求机械填满不适用字段。

开工时按 [运行指南](runtime-usage.md) 核实 doctor/setup、init 等能力。工具缺失时继续研究和设计，单独记录运行阻塞；不把制片任务扩展为 Player/renderer 开发。工程内保存采用的素材、代码与依赖，运行时不需要原网页、原模板工程或开发者机器的绝对路径。

## 1. 产品理解与执行约束

**目标：** 得到足以指导取舍、文案和镜头的产品 brief，并拿到首批真实画面。不能用“做一支高级宣传片”或“让知识流动”代替产品理解。

**输入：** 用户要求、产品网站/资料/源码、可访问状态、已有素材与旧记录。

### 研究产品，同时采集

1. **还原一条实际使用路径。** 用户带着什么任务、提供什么输入、在产品里进行什么关键操作、得到什么输出、在哪里使用结果。优先查看功能页、示例/案例、帮助文档和实际界面；有源码时检查对应入口、功能实现及启动条件。首页口号只是线索，源码中存在功能也不等于当前可访问版本已经开放。
2. **分析受众与价值。** 区分实际使用者、购买/决策者和本片主要观众；围绕最重要的使用场景说明痛点、现有做法和产品提供的改变。受众是推断时注明依据，不把所有可能用户并列成没有取舍的目标。核心卖点写成“能力 → 给用户的结果 → 产品依据”；没有对比证据时不声称领先、唯一或效率提升数值。
3. **确定本片的内容优先级。** 分开记录用户指定必须展示、Agent 为解释产品选择展示、可选补充三类内容。不是每项功能都要拍；但用户指定项不能为适配模板悄悄删掉。将产品事实与影片任务分开：产品用途是它帮用户完成什么，影片用途是这次面向谁、在哪个场景、希望引导什么行动。
4. **访问到关键状态时就保存素材。** 核对已有素材后，采集能说明主流程的真实页面、输入/结果状态和代表性官方案例，保存到 `assets/` 并登记来源。案例选择看它能证明什么、是否与受众有关、是否有可用清晰度，不只看配色合不合品牌。此时获取能支持内容与方向判断的素材；不先穷举所有页面，也不把采集全部推迟到分镜后。
5. **明确可证明的边界。** 分开标记实际操作观察、官方文档宣称、官方作品案例、Agent 推断和未知。静态截图不能证明操作过程；官方作品不能证明它由某次演示输入生成；案例展示也不自动等于客户背书。无登录态时先找公开演示/帮助图/用户已有截图，不能凭空补产品交互。
6. **轻量收集品牌。** 一个可用 Logo、主题色及来源即可起步，记录官方规定还是网页观察。Logo 是素材，主题色是后续 style 的输入；只有明确规范要求时才补充品牌字体等。组织规则见 [brand-kit.md](brand-kit.md)。

采集前处理个人、客户、内部或密钥信息；按项目约束使用已确认公开、脱敏、冻结或虚构的数据。虚构数据要与真实功能验证区分。等待页面字体、图片和目标状态就绪后保存；记录访问受限、未加载、低清等问题，不以这些画面冒充合格素材。

### brief 应回答的问题

将以下内容写进 `records/brief.md`，简短项目可以用段落，复杂项目可用表格；重点是答案具体且有依据。

| 内容 | 要写清什么 |
| --- | --- |
| 产品定义与使用路径 | 谁在什么场景，用什么输入，通过哪些关键操作，得到什么结果；当前可证实的边界 |
| 主要受众与痛点 | 本片优先面向谁，他们原先怎样完成任务、哪里困难；事实与推断分开 |
| 核心价值与优先级 | 哪些能力值得展示、为什么对该受众有用、依据在哪里；必展示/选展示/不展开 |
| 影片任务与主信息 | 发布/演示场景、观众看完应记住的一句话、行动指引；不要以口号代替产品定义 |
| 执行约束 | 语言、画幅、尺寸、fps、时长或范围、音频选择、数据口径、可访问环境、交付范围 |
| 证据与素材 | 已观察/仅宣称/推断的区分，已保存文件、可展示状态、素材缺口及处理方式 |

另附简短执行决策表：`用户要求或项目事实 | 对本片的影响 | 执行决定 | 依据/待补项`。例如“无声播放”意味着信息必须靠画面与文案成立、音频时间线为空；不是先做有声片再关闭播放器音量。缺省规格由 Agent 根据用途决定并标记，不需要为每项默认值提问。

证据表在研究时建立、后续补上镜头编号：

| 功能/卖点与优先级 | 证据及可信边界 | 已采本地文件与状态 | 拟展示方式 | 缺口与处理 |
| --- | --- | --- | --- | --- |
| 用实际产品内容填写 | 来源页面/文档/版本；已操作或仅有说明 | 路径、展示了什么、清晰度限制 | 真实交互/结果特写/官方案例/明确示意 | 补采、限定措辞、替代证据或必要提问 |

**进入下一步的条件：** 能具体说清产品的输入、关键操作和输出，已确定主要受众、主信息与必展示项，并有支持方向判断的真实素材。必展示项逐项有证据/素材或明确缺口处理；不能仅写“后续补图”。无法获取某个操作时可以推进独立镜头的设计，但该操作段保持待补，不以概念界面宣称已验证。用户要求必须实拍而关键状态无法访问时，提出最小必要问题。

**常见偏差：** 只摘首页标题；受众全部列上；把影片目标当产品用途；拿漂亮案例替代功能理解；把整理 brand kit 当第一阶段主体。

## 2. 参考拆解与视觉方向

**目标：** 在全片实现前，用真实素材验证参考的镜头设计能承载目标产品，并确定 style 的表面表达。

**输入：** brief、首批真实素材、用户参考、模板与 style 候选、轻量品牌记录。

### 选择与拆解

1. 按 [模板约定](template-conventions.md) 读取候选 `template.md` 的片子结构、素材要求和换产品指南；按 [Style 约定](style-conventions.md) 读取候选 `style.md`。依据叙事、素材形态、受众与实现条件选择，记录取舍，不仅凭名字选型。可以借用部分连续段落；没有适合模板时自主设计，空目录如实记录，不回退到其他 skill 工程取资源。
2. 完整阅读选中段落的源码和必要附属文件。style 的 demo 只作为表面表达的实现参考，不当模板，也不要求独立运行。记录模板、style、源片的版本或内容标识及可访问位置。
3. **有参考视频就实际拉片。** 先看全片叙事与能量变化，再看选中段落的动作起止、峰值、停留和转场，必要时抽帧/拼接触表并连续回放关键区间。不能只看 poster、源码或静帧就声称看过动态。没有原片时明确以现有代码/样片为依据及无法核验的部分。
4. 为选中段落写拆解表：`参考时间段 | 信息作用 | 主体/背景与尺寸关系 | 主动作、相机与转场 | 颜色职责 | 本片替换与保留/偏离原因 | 源码入口`。记录谁先动、谁跟随、主体从哪里到哪里、镜头如何揭示新信息、前后段如何接上。不要把它缩减成“卡片飞入、标题淡入”。

**设计职责：** 产品事实约束内容；参考决定动作、镜头变化、空间调度、布局、转场与节奏；style 负责颜色、字体及兼容的表面材质。替换不适用功能时保留适合的运动关系，不能让模板创造产品能力。无参考时才按本片目的自行建立这些镜头关系。

**颜色按作用处理：** 分别判断舞台底色、正文、控件、状态、真实内容、语义强调和转场色。主题色默认是局部点缀，真实截图/案例/Logo 保持原色；彩色内容墙、多色渐变、局部高饱和高潮不因此一律去色。style 调整相应色谱和材质，不把所有颜色归并成一个主题色。明确用户要求与品牌规范优先，直接冲突且无法兼容时再澄清。

### 用小样验证，而不是直接铺满全片

- 通常选择 2–3 个有差异的关键画面：例如品牌/主信息、信息密集的产品操作、成果/收尾。使用已采真实素材和接近最终长度的文案，按目标画幅制作 styleframe，观察实际观看尺寸下的字体、构图、信息层级、颜色主次和最大放大清晰度。
- 选最有风险或最有代表性的动作做短动态：检验准备→运动→落定→可读停留→退出，尤其是截图转近景、卡片展开、跨场景共享对象与相机运动。先验证参考的空间和时间关系，再扩展全片。
- 小样可以用轻量静态页面或当前 React 场景，不另建编辑器。已有相同素材形态的可靠验证时可复用并记录；仅有参考片并不能证明换成新文案、截图后仍然成立。
- 将字体、颜色角色、表面处理、关键比例、动作时值与保留的参考关系写进 `direction.md`。从参考读出动效参数，不按品牌色或 style 标签另造一套默认缓动。

**进入下一步的条件：** 真实素材已证明能进入所选构图，关键文字可读，主要动作和转场可实现，方向记录能指导后续场景。无法验证的运动单列为风险，不把静态 styleframe 当动态通过。内部小样检查不自动打开用户浏览器。

## 3. 功能映射与分镜

**目标：** 把产品信息排成有因果、有节奏的镜头序列，再转成帧级实施依据。

**输入：** brief、参考拆解、已验证方向、素材与缺口、音频约束。

1. **先做功能到画面的映射，再排时长。** 为每项必展示内容指定能证明它的页面状态/操作/结果，匹配适合的参考段落或自主设计。记录 `功能/卖点 → 证据与素材 → 镜头编号 → 观众会看到的变化`。功能名出现在字幕里不等于展示过功能；无法操作时可采用确实展示该功能的官方演示、帮助图或结果截图，并限定它能证明的范围。明确示意可以解释流程，但不能据此勾选“真实功能已展示”；相应必展示项仍待补。Agent 自选的内容可调整并记录，用户指定项不可自行降级或删除，确需改变范围时提出必要澄清。
2. **组织叙事与能量。** 明确开场引入什么、功能段如何推进、哪里提供结果证据、结尾让观众做什么。各镜头回答“新增了什么信息”，删掉只重复 tagline 的段落。变化来自内容与参考的动作安排，不硬套每镜不同特效；连续同构镜头需要有比较、递进或节奏上的理由。
3. **提前决定声音关系。** 用户要求无声时跳过选曲与音效，按纯视觉可理解来规划。用户指定 BGM，或镜头依赖卡点时，先选定可用音源、分析段落和候选重音并试听校准，将重要动作绑定音乐锚点。`analyze-audio` 的瞬态不是已验证节拍。无卡点要求可先预留节奏空间，阶段 6 再细化。
4. **写完整分镜。** 每镜至少说明信息目标、实际展示内容、素材与来源、文案、主体起止位置/比例、主动作与相机、入出转场、时长、声音关系、参考区间/源码入口。一个镜头聚焦一个主要信息和动作弧，辅助动作不能抢走理解任务。
5. **落实帧预算。** 确定尺寸、精确 fps、总帧数和半开场景区间 `[start,end)`。分别分配进入、动作、落定、可读停留与退出；信息密集页面要给读懂的时间，不能把运动时间当可读停留。记录转场重叠、层级、共享对象和接缝处的连续状态，不重复计算时长。
6. **建立实施锚点。** 给关键动作、文字落定、点击与结果出现设置 scene/marker，声音引用相对锚点。记录每镜的源码入口、验收帧/区间和仍待补采内容。改造长模板时检查组件内部全局时间、镜头边界及音频引用，不能只改场景列表就认为完成重排。

可将 `storyboard.md` 的信息分为两表，避免一张表过宽：

- **叙事表：** `镜头 ID | 信息目标与证据 | 实际画面/文案 | 参考段落与改造 | 素材/缺口`。
- **实施表：** `镜头 ID | 全局帧区间 | 主动作/相机/对象状态 | 停留与转场 | marker/声音 | 源文件与验收帧`。

**进入下一步的条件：** 必展示项全部有落点，文案没有超出证据，素材缺口有具体处理；时长包含读图与呼吸，参考动作有可执行描述，镜头和声音共用时间依据。Agent 完成一致性检查即继续，不等待分镜审批。

## 4. 按分镜补采与整理素材

**目标：** 使素材满足每个镜头的实际裁切、放大、分层和动作需要。这里是补采，不是第一次打开产品。

**输入：** 分镜、首批素材与来源、可访问产品状态、待补项。

1. 先核对已有文件是否满足镜头要求；满足就复用。只补拍缺失交互、特定页面状态、更高分辨率原图或独立元素。官方案例优先获取实际可用画面，不能把低清缩略图直接铺满画面。
2. 根据镜头选择素材组合：整页/窗口截图保存上下文；元素切片支持独立动作；需要元素离开原位时准备干净底板或可靠遮罩，避免背景中残留第二份；需要相机与元素对齐时记录坐标和尺寸。不是每镜都强制采集所有组合。
3. 使用 `capture` 保存 `page.png`、按需的 `element-*.png` 与 `capture.json`。当前工具默认 1440×900 CSS 视口、2× 采集；不同视口或复杂状态按实际工具能力准备，不能假称已得到 1920×1080 页面素材。`capture.json` 的元素 bounds 来自视口坐标；用于整页纹理时需记录滚动偏移、截图比例和裁切原点，统一坐标系后再计算飞行目标和遮罩。需要更多几何记录时另存，不假定工具自动生成整页 layout 文件。
4. 等待明确页面状态、字体和图片完成；有懒加载、实时数据或动画时检查实际画面后再采集。重复采集应能重建同一状态，记录 URL/版本、视口、选择器、交互步骤和数据处理方式；复杂采集按需保留脚本。
5. 按最终出镜尺寸检查清晰度。例如原本小卡片随后放大为主画面，应按放大后的像素需求选择源图，而非按初始卡片大小。文字发糊先查源图分辨率、缩放和栅格化，不能用景深/模糊效果掩盖。
6. 录屏或案例视频记录源入出点、时长、fps/时间戳、是否包含声音和预计取帧方式；只保留需要的片段，按 [运行契约](runtime-contract.md) 处理裁切、变速与越界。浏览器内嵌视频声音须显式静音或纳入统一音频时间线。

**产物：** 满足分镜的本地文件、来源与使用依据、采集/裁切记录，以及更新后的功能→镜头→素材关联。品牌资源按需补到 brand kit，产品证据继续放 assets。

**进入实现的条件：** 当前镜头需要的真实状态与素材已经可用，最大放大清晰度和坐标对应检查过。独立镜头可以先推进；缺少必需素材的镜头不能以静默占位标记完成。关键材料不可获得时回到分镜调整表达；用户硬性要求受阻时如实说明缺口。

## 5. 逐镜头实现与检查

**目标：** 按帧级分镜实现参考的动作与空间关系，每完成一镜就取得实际画面证据。

**输入：** 已检查的方向与分镜、最终使用素材、选中参考源码、runtime 环境。

1. 建立/复用独立影片工程，入口为 `film.tsx`，用 React + TypeScript 组织场景。按 [运行契约](runtime-contract.md) 统一帧、配置、素材和音频时间线。采用的源码和素材保存在本工程，锁定依赖与参考版本；不修改模板本体。
2. **先读实现，再适配。** 开始一个参考段落前，读对应说明、准确源码和已有验证画面，查清布局、遮罩、缓动、时值、对象生命周期与已知近似。只读模板标题后重写一套泛用卡片动画，会丢掉参考真正值得借鉴的细节。
3. 先实现主体构图、相机与关键动作，再替换文案/真实素材和表面属性。页面元素应落入真实槽位，文字/指针/遮罩与截图使用同一坐标变换。跨镜头承接对象保持位置、大小、层级及速度关系；不要让每镜都从零淡入。
4. 对每镜检查首帧、入场中、动作峰值、落定、退出与交界前后帧；在 Player 连续观察完整动作弧。保存实际检查的帧号、图片/区间、版本和问题。静帧判断构图和细节，动态判断节奏、接缝、闪烁与可读停留，两者不能互相替代。
5. 检查指定帧、跳转、倒退与连续播放一致。动画状态只能由当前帧、输入、配置和固定种子决定；不能依赖墙钟、未播种随机、累计定时器或此前 React 状态。字体、图像、视频目标帧须真正就绪后才捕获。
6. 修改后重看受影响镜头及前后接缝；完成一轮迭代后连续回看全片，检查整体节奏与重复信息。使用 prepare/still 和后台 Player，无需自动导出 MP4。工程内容改变后重新准备并重启使用旧版本的预览服务，避免混用新源码与旧媒体。

**进入下一步的条件：** 每镜有检查证据，全片能按共同时间线连续播放，参考动作/布局得到实际落实；未解决问题明确列出。工具无法验证动态时保持“未验证”，不能以编译成功代替影片完成。

## 6. 声音编排

**目标：** 在画面节奏稳定后完成音乐、音效与已有配音的层次和同步。卡点所需的前期选曲在阶段 3 完成，此处细化。

**输入：** 稳定画面、声音方向、可用音源及使用依据。用户要求无声时，音频时间线保持为空，检查所有内嵌媒体均未自行出声，然后进入相应范围审查；不擅自补 BGM/SFX。

- 选曲要放进实际画面判断情绪、段落和高潮，不能只单听曲子。音源来自用户、本 skill 实际可用资源或有使用依据的素材；原模板的混合配乐不能自动视为可复用音乐库。
- 按画面动作挑选 SFX：运镜、揭示、落地、打字等分别考虑音色与密度。可辨识的真实交互优先考虑贴合动作的声音，不因按钮存在就铺通知音，也不为每个小元素加同样的冲击音。
- 将事件集中在共享音频时间线，使用 scene/marker 加偏移定位，明确源入出点、工程起止帧、增益、淡入淡出、循环/短缺策略。长样本明确截取长度，避免尾音覆盖后续镜头；连续动作控制音量和密度，避免机械连发。
- 按素材实际电平和混音结果调层次，不复制固定音量系数。检查 BGM 是否盖住配音或关键 SFX、是否削波、起止是否突兀、循环是否有接缝、结尾是否留足收束。
- 画面时序一变，先更新相对锚点和裁切，再逐条复查受影响声音；镜头整体改时还要检查全片音乐结构。共享时间线同时驱动 Player 和最终混音，不维护第二套导出声音时序。

**产物与检查：** 工程内音源及来源、完整音频事件、混音和同步证据；无声片记录明确静音。无法实际听音时如实保留听感缺口，波形/技术测量不能替代试听，更不能为此擅自上传外部模型。

## 7. 独立审查与修复

**目标：** 评测实际影片是否落实产品任务、参考设计和高端商用定制标准。规则与评分以 [review.md](review.md) 为准，本阶段组织证据和返工。

1. **制作 Agent 先自检。** 全片回看并逐项核对 brief：必展示项是否出现了有证明力的画面，文案/案例是否被误解，参考运动与布局是否保留，style 和品牌色职责是否正确。再查文字、材质、素材、转场、确定性和适用的声音项。把可自行发现的问题先修掉，不把首检交给用户。
2. **给独立 subagent 当前版本证据。** 按 [审阅指引](reviewer-prompt.md) 使用干净上下文，提供 brief、方向、功能映射、分镜、实际参考及对应区间、可观察的完整预览、关键帧和技术记录。不得以“应当通过”、目标分数或制作辩解引导评测。
3. **区分范围。** 可先做 visual 六维评测，声音与同步保留 deferred/null；完整七维每项均 ≥7.5、没有阻断且必要证据齐全才可称商用通过。用户要求无声时使用 visual，并另记空音轨/无意外发声的技术检查；当前评测工具的 commercialStatus 仍为 incomplete，交付时说明“视觉范围通过，按要求无声”，不为取得七维结论添加音乐或编造听感分数。缺少独立评测或动态观察能力时保持未完成，制作 Agent 自评分不能替代。
4. **版本化复测。** 用 `review-pack` 生成新证据包，独立评审后用 `review-check` 校验。问题给稳定 ID、镜头、帧号/时间码、可观察现象和修复目标。修复后用 `--previous` 关联旧报告生成新包，旧评分不继承，旧阻断不靠删除条目消失。

按问题回到对应阶段：

| 问题 | 回到哪里 | 连带更新 |
| --- | --- | --- |
| 用途/受众理解错误，卖点无依据 | 1 | brief、素材证据、受影响方向和镜头 |
| 模板不适配，style 覆盖了参考运动，配色职责错误 | 2 | 方向、小样、受影响实现 |
| 漏展示功能、叙事重复、阅读时间不足 | 3 | 分镜、时间线、声音锚点 |
| 素材低清、状态不对、坐标错位 | 4 | 素材及来源、使用镜头 |
| 闪烁、跳帧、接缝或动画工艺问题 | 5 | 关键帧与动态检查 |
| 声部、裁切、同步问题 | 6 | 共享混音与试听/测量 |

**产物：** 与当前版本绑定的报告、问题及修复证据、本轮范围状态和完整商用状态。不能以平均分抵消单项不足。修复后复查关联镜头并全片回看；同一问题连续修复仍无进展时重新检查根因/方案并说明剩余缺口，不降低标准盲目重试。

## 8. 按需预览与导出

**默认交付：** 可预览工程及准确的审查状态，说明工程位置、规格和未完成项。视觉通过只说明视觉范围；源码完成、可运行、预览工程通过、实际 MP4 通过是不同结论。

- 用户要求预览时，准备当前版本并打开 Player。用户请求看初稿时可打开尚待审查的工程，明确其状态；不为展示初稿强行宣布通过。未要求时内部检查使用后台运行，不自动打开浏览器或展示本地服务。
- 仅请求预览或表示满意不触发导出；用户满意并明确要求导出后，才用相同场景、帧逻辑、素材和音频时间线生成 MP4。已有明确导出授权不重复索取，不自动增加带声/无声等多版本交付。
- 对实际 MP4 按 [成片检查](review.md) 核对尺寸、fps、帧数/时长、编码、画质、首末帧、音轨与同步，实际播放及抽帧对照；渲染进程成功不代表成片通过。修复后重新导出、复测。
- 本流程不打开可视化编辑器，不导出其他剪辑工程，不发布作品或附加推广流程。

## 续作与变更

续作先检查现有工程与记录，不因文件存在就认定阶段已完成。尤其旧 brief 只有口号、目标受众/功能依据不明或没有真实素材时，重新执行第一阶段的缺失部分，再检查下游镜头是否需要重做；不能只追加一句新要求就宣称研究更新完毕。

按变更影响回到最早相关阶段，保留仍有效的证据和独立镜头。内容/素材/时序修改后更新记录与内容版本，旧审查结论不能用于新版本放行。每次交接说明“已完成并验证什么、剩余什么、下一步依赖什么”，无需重新询问用户已确定的要求。
