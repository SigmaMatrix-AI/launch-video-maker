# 制作流程

按以下流程自主推进制作。执行前核对 [运行契约](runtime-contract.md) 与实际可用工具；不能把设计约定当作现成工具。

阶段产物是工作记录，不是用户确认关卡。已有材料可增量复用；缺项若能根据产品证据合理推断，记录判断后继续。

## 工程与记录

每支影片使用独立工程，和 skill 源码分开。建议组织如下，文件名可调整，但职责与关联必须清楚：

```text
<film-project>/
  brief.md                 产品证据、受众、卖点与制作约束
  direction.md             品牌依据、视觉方向、参考与改造决策
  storyboard.md            场景、全局帧区间、内容与声音锚点
  brand-kit/               本片品牌素材与来源记录
  assets/                  截图、录屏、其他视觉素材及音频
  assets/sources.md        非品牌素材的来源与采集记录
  src/                     React 场景、工程配置及共享时间线
  .lvm/review/             版本化审查报告、关键帧、修复证据
  exports/                 用户触发导出后才产生的成片
```

始终使用当前工程内的素材引用，避免开发者机器绝对路径和对参考工程的外部依赖。brand kit 的组织与来源规则见 [brand-kit.md](brand-kit.md)；技术字段见 [runtime-contract.md](runtime-contract.md)。

## 1. 理解产品并建立 brand kit

**输入：** 用户要求、产品资料、可访问的网站或源码、已有截图或录屏。

**动作：**

- 只读检查产品定位、主要功能、真实使用状态和品牌表现，明确受众、核心卖点、用途、行动指引、语言、画幅、时长及声音约束。
- 对每项关键宣称记录产品依据；不从装饰画面推断产品已具备某项功能。
- 在当前影片工程建立 `brand-kit/`，收集 Logo、字体、品牌色、规范及依据。明确标记用户指定、官方规范、产品观察和 Agent 推断。
- 清点可复用素材、可采集页面状态和缺失项；采集前处理页面中的敏感或不适合展示的数据。

**产物：** 产品简报、约束与假设、初始 brand kit、素材清单。

**衔接：** 产品事实和明确约束成为设计、分镜、实现及审查共同依据。必要输入无法推断时才提问，品牌素材尚不齐全不妨碍其他独立工作。

## 2. 选择风格和参考模板

**输入：** 简报、brand kit、用户参考、候选目录。

**动作：**

- 按 [模板约定](template-conventions.md) 和 [Style 约定](style-conventions.md) 发现候选、读说明，再完整阅读选中资源及相关源码。
- 根据叙事适配性、品牌调性、素材要求与技术可用性自主选择。允许引用多个模板的局部，不为“选中模板”硬套完整结构。
- 记录参考路径和版本、借鉴片段、保留的设计特征与计划改造。将 style 的自由描述转化为本片可执行的字体、布局、色彩、动效与质感方向。
- 空目录明确记录“暂无内置参考模板”或“暂无内置 style”，依据产品与用户要求自主设计。不得回退到读取 video-shotcraft 资源。

**产物：** 视觉方向、参考及改造决策；有助于判断时制作少量关键画面草图。

**衔接：** 将确定的方向交给分镜和实现；没有现成参考不构成等待用户选型的理由。

## 3. 编排分镜与声音方向

**输入：** 产品信息优先级、视觉方向、素材清单、音频约束。

**动作：**

- 确定叙事顺序及各场景承担的信息；规划画面主体、文案、布局、主动作、转场、可读停留和素材需求。
- 指定画幅、尺寸、fps、总帧数与场景全局帧区间；记录转场重叠及层级。直接进行场景设计，不引入镜头卡或镜头选择系统。
- 提前确定音乐情绪、能量变化和 SFX 方向。用户指定 BGM 或设计依赖卡点时，先选定音源并分析段落、拍点和重音，再锁定分镜。
- 将声音事件与动作关键帧关联；BGM 尚未选定且不要求卡点时，先保留节奏预算，在声音阶段落实。

**产物：** 分镜表及声音计划。每个场景至少可追溯到信息目标、帧区间、画面/文案、转场、素材来源或待采集项、声音锚点。

**衔接：** Agent 自检后直接进入采集；分镜定案是内部制作基线，不是用户审批点。

## 4. 采集并整理素材

**输入：** 分镜、素材清单、brand kit 与可访问的产品状态。

**动作：**

- 先核对已有文件的清晰度、画幅、页面状态和可用性，再采集缺项，避免重复截图或录制。
- 表现真实产品功能时优先采集真实页面；抽象演示与概念视觉应清楚区分，不能暗示不存在的能力。
- 保存截图、录屏及其他素材到本工程，记录来源、采集状态、尺寸、时长、用途和必要的使用依据；品牌素材归入 brand kit。
- 检查字体、图片和页面状态加载完整，录屏没有误操作或无意曝光的数据。素材尺寸应能支持预计的裁切与放大。

**产物：** 本地可用素材、来源记录、补齐的 brand kit、分镜到素材的引用关系。

**衔接：** 无法获得关键素材时调整表达或报告必要缺口，不使用静默缺图占位；回写受影响的分镜。

## 5. 实现 React 影片

**输入：** 分镜、视觉方向、参考源码、brand kit、已采集素材。

**动作：**

- 用 React + TypeScript 组织场景，按 [运行契约](runtime-contract.md) 以帧计算画面状态。源码和素材归属当前工程，不依赖 Remotion。
- 将模板中合适的实现借用、改写或拆分，将 style 与品牌依据落实到本片源码，不要求模板预先支持每一种 style。
- 统一配置和视听时间线；场景引用 brand kit 中选定的 Logo、字体与派生品牌值。
- 每完成一个场景检查起始、动作峰值、落定、退出及交界关键帧，并连续观察动态表现。检查乱序取帧是否与连续播放一致。

**产物：** 场景源码、共享配置与时间线、逐场景检查证据。

**衔接：** 有运行能力才可进行动态验证。缺少必要工具时，记录已完成的设计/源码及未验证项，说明阻塞；不擅自扩展任务去开发 Player 或 renderer，也不将未验证的阶段标记为完成。

## 6. 完成声音编排

**输入：** 节奏稳定的画面、声音计划、BGM/SFX 素材。

**动作：**

- 细化源片段裁切、起止帧、音量、淡入淡出、循环接缝与关键动作的声音落点。
- 为音乐、音效及已有配音分配层次，检查可听见性、结尾收束、突兀截断和削波。
- 从共享音频时间线驱动预览和最终混音，不能各自手写另一套时间。
- 画面时序变化时同步重算声音锚点；若影响音乐结构，回到分镜阶段调整并复查相关场景。

**产物：** 工程内音频素材及来源、完整音频时间线、试听与同步检查证据。

**衔接：** 画面与声音作为同一版本进入审查；不能用单独音源试听证明整片同步。

## 7. 审查与修复

**输入：** 当前工程版本、简报、方向、brand kit、分镜、关键帧及可播放的完整视听内容。

**动作：**

- 制作 Agent 先按 [review.md](review.md) 自检，再派未参与制作、干净上下文的独立 subagent 评测影片。
- 可先执行visual范围的六维独立审查，听感保留deferred/null；完整商用审查仍须对七个维度逐项评分并给出证据，任何单项低于 7.5、必要项无法验证或存在阻断问题都不通过；平均分不参与放行。
- 使用版本化证据包与 [独立审阅指引](reviewer-prompt.md)。根据稳定问题id、帧号/时间码修复，更新相关源码、品牌素材、分镜和音频记录，再生成--previous新包交由独立评测复测；不继承旧分数或删掉旧阻断。

**产物：** 预览工程审查报告、七维评分、修复记录、版本明确的通过或未通过结论。

**衔接：** 达到高端商用定制标准且检查通过才按可预览工程交付。没有 subagent 或动态/音频证据时标记未完成评测；不能用制作 Agent 自评分替代独立审查。

## 8. 按需预览与导出

**输入：** 审查通过的工程、用户的预览或导出请求。

**动作：**

- 默认说明工程位置和审查状态。用户未要求时，不自动打开浏览器或展示本地服务；内部后台检查不打断用户。
- 用户要求预览时，运行能力完备才打开轻量 Player。仅请求预览不触发 MP4 导出。
- 用户满意并要求导出后，用相同场景、帧逻辑、素材与音频时间线生成 MP4。已有明确导出授权不重复索取。
- 按 [成片检查](review.md) 验证实际输出的画质、声音、同步与规格；发现问题修复并重新导出、复测。

**产物：** 按需打开的预览；仅导出分支产生 MP4 和对应成片审查报告。

**衔接：** 预览通过不代表编码成片通过。用户修改内容后，应更新版本并重查受影响项目；时序修改还需复查全片音画同步。

## 工具落点

开始时用 doctor/setup 核实环境，init 建立工程与 brand kit。方向确定后按 [制作工艺](production-craft.md) 完成 styleframe 和短动态。采集阶段用 capture；卡点前用 analyze-audio 并试听校准。实现阶段用 prepare/still 和后台 Player；声音变更重新准备混音。独立审查用 review-pack/review-check。用户要求预览才 preview --open，要求导出才 render，随后 inspect 和实际视听复查。见 [运行指南](runtime-usage.md)。
