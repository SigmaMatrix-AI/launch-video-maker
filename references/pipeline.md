# 自主设计：定调性 → 定故事 → 做质感

本页用于 Agent 自规划。模板路线按 [模板流程](template-conventions.md) 执行。记录示例见 [阶段产物](stage-deliverables.md)，画面与动作判断见 [Good / Bad 标尺](eval.md)。

## 准备：最小产品研究

只读检查用户提供的页面、源码、录屏或截图，确定受众、场景、输入→关键操作→结果、最多三个利益点、必展示内容和 CTA。记录真实素材路径、来源和使用依据；不要把剪辑压缩的等待时间当作产品性能。

收集 Logo、明确品牌要求、画幅、目标时长、语言及声音要求。缺品牌数据可用中性默认值并说明；缺产品事实则查证或询问，不能发明。将简短结论写入 `records/brief.md`。这是第一步准备，不另加用户关卡；已有有效研究直接复用。

## 1. 定调性：三个方向，一次选择

**输入：** 产品简报、真实素材、明确品牌/参考要求。

选同一个代表内容，做 A/B/C 三张效果图，保持文案、功能和画幅可比。三个方向在排版、视觉语言、材质或空间组织上有实质差异，不能只换配色，也不靠换故事制造差异。可从 `styles/` 的实际资源或参考方法出发。

按已有工具能力生成效果图、截图或静态设计，优先采用可获得的产品素材。只做足以判断调性的代表画面，不展开三套影片、完整分镜或精细运动系统。指出缺失资产和实现风险，避免承诺无法兑现的效果。

**交付：** 三张可查看的效果图、各自一句差异、推荐与理由；写入 `records/direction.md`。建议保存为 `assets/directions/a.png`、`b.png`、`c.png`。

**确认：** 用户选方向后进入第二步；都不满意则按具体反馈修改候选，留在第一步。已有明确代选授权则记录自主选择及授权原话后继续；沉默不能自动默认选 B。

## 2. 定故事：视频讲什么

**输入：** 已选方向及选择依据、产品事实、必展示项。

写 `records/script.md`：开头怎样吸引观众、问题是什么、产品怎样介入、观众会看见什么结果、最后记住什么或做什么。用同一代表案例串起故事；区别主文案、可选旁白、画面事实，不为故事捏造功能。

在 `records/storyboard.md` 用段落 ID、内容目的、简图或画面说明、大致时长对应故事。低保真框图、占位素材均可；粗略时长只用于检查故事规模。标明缺失素材，不以补齐精修 UI 阻塞内容确认。

**交付：** 一版完整故事脚本和简易草稿分镜，让用户判断内容、顺序和必展示项。不要求最终 UI、镜头衔接、精确帧区间、音乐卡点或可播放动态样片。

**确认：** 用户认可当前内容版本后进入第三步；只改受影响段落。已提供并确认的脚本直接复用，明确委托代定则记录后继续。催“快点给草稿”仍按本阶段交付定义执行。

## 3. 做质感：实现、观看、局部打磨

**输入：** 有效的方向与故事决定。保留 `script.md` 主线，用相同段落 ID 给 `storyboard.md` 补充焦点、主体变化、镜头承接、实际时间/帧区间、素材与声音。

1. **先让表达成立。** 按 [eval.md](eval.md) 的 E01–E10 设计独立文字镜头、真实产品动作与对象承接。在独立 `films/<project-id>/` 工程实现，素材和依赖留在工程内，不改模板本体。可先打磨代表段落再扩展全片，这是制作策略，不增加第四个必须审批的关卡。
2. **再让动作准确。** UI 放大当前任务区域；输入、操作、结果依次交接焦点。检查按压、跟随、吸附和落定；镜头运动揭示信息，关键文字保持可读。静止与硬切都可以服务表达，不能为动而动。
3. **安排节奏与声音。** 压缩重复过程，完整展示关键变化，把强调留给核心结果。配乐强度服从已选方向：高能量是候选风格，不是质量门槛；不要求每拍切镜。选有使用依据的音源并试听，时序改动同步更新混音。无声任务保持无声。
4. **看、听、修、复看。** 正常速度完整观看当前版本；有声音则试听实际混音。静帧看排版，连续窗口看动作与接缝。每轮选择最影响观感的问题，按“区间 + 现象 + 案例 ID + 修改动作 + 复看条件”记录。先修产品事实、必展示项、PPT 式主体展示、注意力和阅读，再修材质与微动作。局部修复看本段及相邻接缝，交付前完整复看；时序变动复核声音。
5. **独立审阅与交付。** 按 [技术评测协议](tech.md#质量保证) 让未参与制作的审阅者检查当前版本。七维门槛不是“很贵”的认证；缺观看、试听或独立审阅就标未验证。提供已核实可用的本地预览、工程与检查状态，吸收用户的具体反馈。明确要求导出后再检查实际 MP4。

第三步的审阅上下文需包含 `script.md`，通过已有 `reference` role 接入，见 [记录接入](stage-deliverables.md#接入现有审阅)。没有脚本的老工程沿用已有简报/分镜，不编造历史确认。

## 续作与成本控制

先读方向、脚本、分镜的当前版本和用户反馈，再判断本次范围：

| 情况 | 下一步 |
| --- | --- |
| 当前方向未选择 | 第一阶段，只做选择所需产物 |
| 方向有效、故事待确认 | 第二阶段，只完善故事/粗分镜 |
| 方向和故事有效，只改 UI、按钮、转场或节奏 | 第三阶段，局部修改并复看受影响位置 |
| 改变产品主线或必展示内容 | 回到受影响的故事段落，保留仍有效的方向 |
| 改变整体调性 | 回第一阶段，复用仍有效的产品事实和故事 |
| 初稿存在但无确认依据 | 执行明确授权的局部修改，记录确认缺口；继续展开需取得相关决定或代定授权 |
| 明确委托方向/脚本由 Agent 决定 | 在授权范围代选、记录后继续，不重复请批 |

只重做受影响素材和片段，不每轮重读全部参考、重写整片或重复渲染已验证内容。预算限制沿用用户要求；有真实 token 用量才记录，无数据就只记录生成和返工次数。若一轮修改后主要差距没有改善、或剩余分歧属于偏好，展示具体片段和备选改法让用户定夺，避免无上限自主打磨。
