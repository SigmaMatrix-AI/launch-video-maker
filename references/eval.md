# Good / Bad：从换页到视频表达

创作时先选适合当前内容的方法，第三步用实际播放定位差距。案例 ID 保持稳定；反馈引用 ID 方便局部修改，不要求每条片子套齐十种招式。文字与布局先看 E10，动作与承接先看 E01–E03。

## 十条可观察的质量标尺

| ID / 目标 | Good | Bad | 判断关键 |
| --- | --- | --- | --- |
| E01 主体动作 | 选中反馈→合并条目→排好优先级，操作产生新状态 | 截图不变，只有背景光晕、粒子或整图缩放 | 去掉装饰后，主体是否仍在讲述变化？ |
| E02 对象承接 | 上一镜选中的卡片保持可辨认，成为下一镜主角 | 每镜清空画面，再生成另一套元素 | 能否指出前后是同一个对象或它的成果？ |
| E03 注意力交接 | 输入框→操作控件→结果依次成为焦点 | 标题、光标、UI、背景同时抢动 | 此刻该看哪里是否明确？ |
| E04 UI 任务聚焦 | 放大正在选择的行，保留理解操作所需上下文 | 完整后台截图旁配一段小字介绍 | 不暂停，能否看懂关键操作与结果？ |
| E05 镜头有用途 | 推近看操作，拉远揭示该结果属于完整作品 | 每段都旋转、倾斜、推拉，信息并未变化 | 镜头运动揭示了什么？ |
| E06 动作有落点 | 按下短促、拖动跟手、释放后吸附，结果准确落定 | 所有元素同款滑入/弹簧，落定后仍抖 | 起动、推进和结束是否符合对象角色？ |
| E07 节奏有轻重 | 次要操作压缩，关键变化完整，结果留到读完 | 等长换页，或一直快切没有落点 | 重点是否获得更多注意和时间？ |
| E08 核心揭晓 | 最大尺度与最强变化留给关键成果 | 每个小图标、标题都像高潮 | 看完能记住哪一次改变？ |
| E09 有目的的停留 | 结果、品牌与 CTA 稳定展示，给理解与记忆留空间 | 为了保持“动感”，文字和卡片一直漂浮 | 静止是否帮助观众读懂，而非拖延？ |
| E10 文字独立成镜 | **标题和文字单独镜头出现，并有高亮词或动效** | **标题和配图左右构图、上下构图，像 PPT** | 文字是否有自己的视觉表达，而非长期解说配图？ |

E10 是自主设计的默认宣传表达准则。例如先独立呈现“一份内容，多种语言”，按语义强调“一份 / 多种”，落定可读后再进入产品演示。保留真实 UI 内必要的页头、导航、按钮和语言标签；不要误删产品信息，也不要求每个字跳动。明确要求保留构图的模板按约定执行，用户具体要求优先。

这些 Good / Bad 是制作建议与反例，不等于两条参考片逐项都使用了同一方法。静止、硬切、淡入均可成立；问题是整片反复换页、主体没有变化。不要靠给每个元素加弹簧补救。

- **Introducing Google Vids**：`/Users/mac/Downloads/YTDown.com_YouTube_Media_4SCjXcBeW1E_Introducing-Google-Vids_001_2160p.mp4`。

证据范围：全片稀疏概览、四段 4 fps 时序采样，以及实施时重新提取的关键帧。下述时间是定位窗口，不是精确剪辑点。支持布局、状态和对象关系描述；没有完整正常速度观看/试听证据，不认证细微缓动、完整节奏或音画同步。另一台机器无法读原片时保留文字观察及来源，明确未重新观看；不虚构缩略图、声音或精确时间。精细模仿前重新观察可用原片。

### C01 · LangEase 约 10–14 秒：过程变成完成

- **表达目标：** 让“进行中→完成”成为一次可见揭晓。
- **观察到：** 设备画面接出蓝色带状形态，随后是进度条与递增数字，约 12.5 秒达到 100，约 13.25 秒出现 Done 和勾形反馈。
- **可借用的判断：** 状态改变承担叙事，注意力从过程到落点；对应 E01/E06/E08。字形、数量和数据必须换成当前产品有依据的内容，不能拿动画速度宣称处理性能。
- **Bad 推演（非原片缺陷）：** 一页写“处理很快”配手机图，下一页写“完成”配勾，只有两页淡入；过程和结果失去对象关系。

### C02 · LangEase 约 15–19 秒：从列表中选出主角

- **表达目标：** 让观众认出当前选中的内容及多个语言版本的关系。
- **观察到：** 卡片排列进入界面列表；指针选中 History Lecture，卡片从列表中突出、放大，随后同一人物画面以多张卡片围绕 Multiple Languages。
- **可借用的判断：** 缩略图、文字和选中轮廓让对象前后可辨认；对应 E02/E03/E05。参考片本身包含文字与图片同屏，不能将它说成 E10 的逐镜证据。
- **Bad 推演：** 展示整页列表后直接清空，下一页出现无关联的几张卡与“多语言”标题；观众不知道这些成果来自哪里。

### C03 · Google Vids 约 10–16 秒：请求带着素材生成大纲

- **表达目标：** 把“用已有资料创建视频”的功能变成具体过程。
- **观察到：** Slides 图标被拖向 sales training video 请求，约 12.5 秒成为请求中的附件；约 13.5 秒出现 Creating，随后展现多行大纲。
- **可借用的判断：** 输入、附件、生成状态和输出有可见关系；对应 E01/E03/E04。当前产品没有这个能力时，只借用因果表达方法，不照搬功能。
- **Bad 推演：** 左边写“智能生成”，右边放完整编辑器截图；没有材料进入或结果出现的过程。

### C04 · Google Vids 约 55–62 秒：素材成为作品的一部分

- **表达目标：** 让素材搜索的结果进入最终作品，收束一次完整任务。
- **观察到：** 输入 Landscape，展示素材网格；选中岩拱夕阳缩略图并突出到前景，再进入编辑器画布，约 61 秒可以看见画布和时间线。
- **可借用的判断：** 同一画面从搜索结果到作品保持可辨认，近景解释操作，较完整视图交代落点；对应 E02/E04/E05。
- **Bad 推演：** 列表页与编辑器页直接互换，成片用另一张图片，无法判断刚才选择的素材是否进入作品。

## 从合格到参考质感

| 层次 | 需要实际观察到的表现 |
| --- | --- |
| 基础合格 | 产品事实准确、关键文字可读、资源与播放可靠、必展示内容完整。七维门槛和证据要求仍见 tech.md。 |
| 有视频感 | 主体状态有变化，焦点有顺序，前后对象有关系；动作与可读停留形成轻重，而非重复换页。 |
| 接近参考质感 | 在上述基础上，文字、UI、镜头、材质、动作与声音形成一致表达；关键操作精确、揭晓有分量，接缝经得起逐帧检查。须观看对应证据，不由分数自动推断。 |

这是诊断层次，不新增评级字段，也不把每维 7.5 改称“很贵”。用户喜好与满意度仍需用户反馈。

## 局部迭代示例

`08.2–09.1s / 选中素材后清空再切编辑器，对象关系中断 / E02 / 保持同一缩略图和标色，移动进入画布再显出上下文 / 复看本段及两侧接缝，正常速度能跟踪选中对象。`

`00–02.5s / 标题长期贴着截图，两边同时要求阅读 / E10+E03 / 独立文字镜头突出关键词，文字读完后进入操作 / 正常速度看清关键词与操作，真实 UI 标签仍保留。`

先处理事实、必展示项、主体变化、注意力与阅读，再做动效和材质细节。修改后保留本轮证据，不沿用旧版通过结论。下面是需要时查阅的制作底线与验收细则。

## 1. 产品：用操作证明价值

- 开头直接展示目标用户熟悉的任务、问题或产品结果。长 Logo 动画和通用口号不能代替产品内容。
- 用一个代表案例串起输入→关键操作→结果。核心功能必须有可见证据；不能只用功能名称、图标和宣传语介绍。
- 前后变化保持同一案例、数据和对象，观众能指出产品具体改变了什么。压缩等待或省略步骤时交代时间跳跃，不把剪辑速度当作产品性能。
- 让关键揭晓展示产品结果：零散来源汇成摘要，一句需求展开成作品，局部成果拉远成为完整项目。选择产品实际支持的变化。
- 结尾保留产品名和一个明确行动：试用、加入等待名单或了解更多。行动与当前发布状态一致，停留到文字能够读完。
- 产品能力、指标、客户关系和案例有来源。截图可裁切、分层或忠实重绘；实际功能、状态含义和第三方标志保持准确。

## 2. 避免 PPT 感：检查主体发生了什么

连看产品演示段，回答：主角是谁？发生了什么变化？下一镜承接了什么？连续多个功能段只能描述“这一页出现、停留、下一页出现”时，重做主体动作与衔接。

| 观察到的症状 | 修改方法 |
| --- | --- |
| 连续多段都是标题＋功能卡，只有淡入、滑入、退场 | 选一项真实任务，将卡片中的内容转成可操作对象，展示触发、响应与结果 |
| 整张截图缓慢放大，画面内没有状态变化或新信息揭示 | 对准具体控件或结果，补齐真实交互状态；缩放用于看清信息 |
| 主体不变，只有渐变、粒子、光晕或背景漂浮 | 将动作放回产品主体；背景降低对比和速度，保留可读的静止结果 |
| 每镜清空画面，再从中心生成另一组元素 | 延续同一对象的位置、形状或运动方向；把选中项展开成下一镜，或让结果成为下一操作的输入 |
| 所有镜头时长、入场方式和动作幅度相同 | 缩短重复操作，完整展示关键变化，延长结果阅读；交替使用局部、整体、动作与停留 |
| 三张功能卡或整排客户 Logo 同时要求阅读 | 按重点逐项展示；客户 Logo 可随重音逐个占据中心，承载形状随标志比例变化；保留准确比例、规定配色与可识别停留 |

**静止不等于 PPT。** 核心结果、关键文案、品牌与 CTA 可以稳定停留；清楚可辨、用于整体背书的 Logo 组也可以静态呈现。硬切可省略重复过程；淡入可交接内容。问题是整片反复换页，缺少产品动作、状态关系和节奏差异。不要靠给所有元素加弹簧、旋转或漂浮来补救。模板任务按约定保留编排，先修内容适配与可读性。

## 3. UI：每个镜头只有一个主角

一个主角指一个视觉焦点，可以是一句话、一个操作区或一组成果；其他元素可以存在，但不同时抢读。镜头内按“输入框→操作→结果”交接焦点。

| 检查项 | 看什么、怎么改 |
| --- | --- |
| 信息密度 | 删除与当前任务无关的导航、设置和段落；保留定位及理解操作所需的上下文，放大关键区域 |
| 字体与尺寸 | 在实际投放尺寸看关键文案和 UI 标签；手机投放另看缩小预览。读不清就放大、缩短或分镜，不能依赖暂停放大 |
| 构图 | 用尺寸、位置、对比和留白明确主角。标题、截图、卡片不必每镜都占相同位置；辅助元素不遮挡操作目标 |
| 配色与材质 | 用中性色承载信息、品牌色标出动作与状态，或采用已定风格的同等层级。渐变、玻璃与发光不能盖住文字和产品 |
| 一致性 | 核对字体、字号层级、圆角、阴影、间距、图标及动效气质；同一组件跨镜头保持一致 |
| 清晰度 | 检查放大后的字形、细线、图片、圆角和遮罩边缘；补高清素材或修复渲染，不用模糊掩盖低清 |

静态参考用于观察主次、留白与材质，不能证明动态质量；原片不可用时不要假装完成了时序评估。

## 4. 动效：触发、响应、落定

- **注意力顺序：** 输入出现→输入完成→操作触发→结果生成。同一时刻突出一个主要动作，背景低存在感；上一项还未读清时不引入新的阅读任务。
- **因果准确：** 光标瞄准真实控件后按下，反馈跟随触发；拖动时对象跟手，释放后才吸附。检查光标位置、命中区域和状态切换，不能先出结果再补点击。
- **状态连续：** 卡片展开为详情，选中文字进入编辑区，输入延伸为结果。形变时容器轮廓连续，旧内容先退出，新内容在可读形态下进入，避免文字交叠或被拉伸。
- **动作有收势：** 按钮轻压回弹、拖动标签稍有滞后、滑块前后缘错时、数字减速落定。选与操作有关的细节，检查落定后没有持续抖动或数值跳变。

| 元素 | 运动方式 |
| --- | --- |
| 按钮、选中态、反馈 | 短促、明确、响应及时 |
| 面板、页面 | 平稳、有方向，能追踪起点与终点 |
| 拖拽、卡片 | 跟手，释放后保留适度惯性并准确落位 |
| 核心成果 | 动作更舒展，揭晓后稳定展示 |
| 背景装饰 | 缓慢、低对比，避免抢占前景动作 |

- **镜头有用途：** 推近看清局部，平移连接相关区域，拉远揭示全貌。核心操作时优先稳定镜头，避免相机、UI、文字同时移动。
- **空间可信：** 3D 透视、光标、截图切片和遮罩共用坐标关系；检查悬浮错位、穿插、裁切和边缘接缝。文字阅读时回到清晰角度。
- **转场有承接：** 逐帧检查交界前后的位置、比例、速度和图层，再正常速度播放。修正一帧闪黑、主体跳位、未落定就切走、音效被截断；不要只看两端静帧。

## 5. 剪辑与声音：给重点留时间

- 重复输入和次要操作快速带过。保留核心变化的完整因果，结果出现后留到关键内容能在正常速度下读完；需要反复暂停才能理解，就简化内容或延长停留。
- 把主要揭晓放在音乐段落或重音上。按压、吸附、落定的可听重音对准视觉接触点；需要提前启动动作才能在重音处落定。
- 同一乐句内可先动作、再停留，不必每拍切镜。为关键揭晓保留更大的画面尺度、动作幅度和声音层次，其他段落降低强度。
- 音效匹配材料与速度：短点击用于按压，掠过声跟随运动，轻碰撞用于落位。连续动作变化音色或强弱，避免每个元素套同一个 whoosh。
- 试听音乐与旁白、音效的实际混音：旁白可辨，反馈可听，响度无突跳、爆音和削波。按投放要求检查响度与峰值；用户要求无声时检查全部音轨为空或静音。
- 音乐剪接与循环处无可听断点，结尾在乐句收束处结束或完整淡出，保留尾音。改画面时序后重新准备混音，复查起、中、尾同步。
- 配乐强度服从已选方向和故事。高能量、清晰重音可作为发布片候选；克制或无声同样可成立，不将快节奏、每拍切镜当作高级感门槛。

## 6. 技术：检查交付的那个版本

- **资源：** 等字体、图片、视频目标帧加载后捕获；无缺字、占位图、加载闪烁、旧图残留和外部绝对路径依赖。
- **时间确定性：** 对起止帧、动作峰值和转场交界帧分别顺序播放、倒退、乱序 seek，再捕获比较。同一帧的对象位置、文字、图片及视频源帧应一致。
- **播放：** 检查起播、暂停、继续和跳转，无卡死、重复帧或意外空白；区分预览性能问题与实际渲染错误。
- **导出：** 用户要求 MP4 后，检查实际文件的尺寸、画幅、帧率、帧数、时长、编码与音轨。首帧为 0、末帧为 N−1；完整播放成片，检查压缩后文字、渐变、首尾和起中尾音画同步。预览通过不能代替成片检查。

具体取帧、资源等待、音频与 render 约定见 [tech.md](tech.md)。

## 7. 记录问题、修复、复看

1. 先正常速度完整看听一遍，再静音复看核心演示；暂停检查排版，逐帧检查动作与转场。每项分别标记已检查或未验证，截图、源码和波形不能代替观看与试听。
2. 每条问题记录 **时间/帧区间＋可观察现象＋案例 ID＋修改动作＋复看条件**。例如：“08.2–09.1s，结果文字仍在缩小且下一标题已进入；先让结果落定，延后标题；正常播放能读完结果后再转移注意力。”
3. 先修产品错误、关键操作缺失、PPT 式主体展示、注意力冲突和阅读问题，再修运动、材质和声音细节。修改后复看当前段、前后接缝及全片；视听节奏改变时同步检查混音。
4. 交付前由未参与制作的独立审阅者检查当前版本。按 [现有评测工具](tech.md#使用现有评测工具) 填写七维评分、证据与问题；不能仅靠平均分掩盖单项问题，也不预填期望得分。

七维评分沿用 tech.md：风格还原、创意与惊艳、动效工艺、设计与排版、质感与细节、声音与同步、技术规格。低于 7.5 表示该维度仍有影响观看或理解的问题；达到 7.5 需有当前版本的实际证据且相关必修问题已解决；更高分需说明超出基本合格的具体表现。分数不能证明观众一定喜欢或转化。

产品演示还需单独核对：核心价值是否由真实案例与可见变化证明。功能名和截图齐全，但关键操作与结果之间缺少依据时，不通过；明确限定为品牌预告或静态宣传的任务按约定范围评估。存在虚假产品信息、敏感信息曝光、关键文字不可读、资源/播放故障、明显音画错位或必展示内容缺失时，不通过。缺观看、试听或独立审阅证据时，结论为未完成，并列出缺口。无声片标记视觉范围与静音要求；有声片未试听不能称完整通过。技术测试通过只证明对应技术项。
