# 预览与渲染技术契约

本文定义长期运行语义。可调用接口、安装和限制见 [运行指南](runtime-usage.md)；环境能力须通过 doctor 与实际测试核实。

## 分工与共享数据

| 部分 | 职责 |
| --- | --- |
| React + TypeScript | 场景、构图、文字、视觉素材与动画状态 |
| 统一帧控制 | 根据指定帧和固定配置计算场景状态 |
| 轻量 Player | 播放、暂停、拖动、逐帧查看、音频试听；不提供可视化编辑 |
| Playwright | 加载同一场景入口，等待指定帧真正就绪后逐帧采集 |
| FFmpeg | 按工程规格编码帧序列、裁切与混合音频、封装 MP4 |

预览与导出共用场景代码、工程配置、素材、帧计算和音频时间线。不得分别维护一套“预览版”和“导出版”动画或音频时序。运行依赖不包含 Remotion，不引用其他视频工程的文件。

## 时间与场景语义

下表规定时间语义，具体类型由 runtime 的 Film、Scene、Asset、AudioEvent 导出。

| 概念 | 约定 |
| --- | --- |
| 工程配置 | 宽、高、fps、总帧数、固定随机种子、资源根、音频输出规格与内容版本 |
| `frame` | 从 0 开始的全局整数帧；有效范围为 `0` 到 `durationInFrames - 1` |
| `fps` | 全片统一、明确记录的帧率；如支持分数帧率，保存精确比值而非近似小数 |
| 时间换算 | 第 f 帧对应 `f / fps` 秒；全片时长为 `durationInFrames / fps` 秒 |
| 场景区间 | 使用半开区间 `[startFrame, endFrame)`，时长为两者之差 |
| 局部帧 | `localFrame = frame - startFrame`，转场中的两个场景分别计算 |
| 转场 | 显式声明重叠区间、图层顺序和合成方式，不能重复计入总时长 |

场景状态由当前帧、固定配置、输入素材和种子确定。随机访问第 f 帧与从头播放到第 f 帧应一致；不能依赖 `Date.now()`、无种子的随机值、累计定时器或之前的 React 状态推进画面。

CSS 动画、视频播放或其他动画库若用于画面，必须能由统一帧显式定位；默认自主播放不符合契约。Player 的实时计时可以决定当前帧，但不能成为场景内部的第二个时间源。

## 资源就绪与取帧握手

运行层须保持以下可观测能力：

1. 装载工程配置、场景、字体、图片和媒体，并报告资源错误。全局初始化完成后才接受捕获请求。
2. 接受“指定帧 + 内容版本 + 请求标识”，驱动 React 更新；不能用固定等待毫秒数替代更新完成信号。
3. 等待该帧 React 提交、布局/绘制及相关异步素材处理完成，包括字体就绪、图片解码、视频目标帧就绪。
4. 返回与本次请求一致的请求标识、已完成帧号和版本。Playwright 校验后才截图；过期请求的完成信号不得解除新帧的等待。
5. 资源失败、超时或帧号不一致时显式失败，报告具体资源/阶段；不把上一帧或占位图当成功结果。

捕获事务覆盖“设置帧 → 等待就绪 → 校验 → 截图完成”。同一捕获实例内事务串行执行，从就绪确认到截图完成期间保持画面与内容版本不变，不接受另一个改变画面的请求；完成或失败后才释放。实时预览的连续 seek 可以取消旧请求，但其完成信号不能用于捕获事务。并行采集必须使用相互隔离的实例。

同一输入重复取帧应可复现。需检查连续、跳转、倒退和快速连续请求；实际实现还须固定捕获视口、像素密度、颜色约定与相关环境，避免不同机器无意改变版式。

## 视频素材准确取帧

为每个视频片段记录源文件、源入点、工程起止帧、播放速度和越界策略。目标源时间由工程当前帧映射得出，不能让 HTML video 按墙钟自行前进。

实现必须处理 seek 完成与目标画面解码/呈现完成的区别。仅设置 `currentTime` 或收到 `seeked`，不足以证明截图对应目标帧。可采用经过验证的浏览器解码握手或预解码序列，但必须明确策略、源时间戳映射及误差。

变帧率素材按源时间戳映射，不能假定帧号与时间恒定成比例。循环、冻结末帧、裁切或不足长度应在编排中明确；不得静默黑屏。内嵌视频声音必须纳入共享音频时间线或显式静音，避免浏览器和混音器重复播放。

## 音频时间线

工程时间线是唯一时序依据。每个音频事件至少应描述：

| 信息 | 语义 |
| --- | --- |
| 标识、轨道、资源 | BGM、SFX 或已有配音；引用本工程素材 |
| 工程起止帧 | 半开区间，决定何时出声与结束 |
| 源入点/出点 | 明确使用秒或样本单位，不混用工程帧率和音频采样率 |
| 播放速度与循环 | 默认正常速度、不循环；改变时明确重采样和接缝策略 |
| 增益与包络 | 统一线性增益或 dB 的转换规则；淡入淡出及关键点使用明确单位 |
| 同步锚点 | 对应动作帧、节拍或重音位置，用于时序变化后重算 |

工程起止帧决定事件的输出时长；源入出点定义可用片段，播放速度决定其映射长度。映射后超过事件终点则截断；不足且未循环时，事件必须明确选择补静音或缩短工程区间，否则校验失败。循环必须显式启用，并声明源循环区间和接缝策略；不得自动循环或由不同播放后端自行补齐。增益包络和淡入淡出统一以事件内的工程局部帧为坐标（全局帧减事件起始帧），不随源播放速度改变其工程持续时间；包络越界应校验失败。

源采样率可以不同，混音时统一到工程声明的输出采样率和声道布局。用统一规则把工程时间映射到样本位置，避免逐段累加舍入误差。尾音、淡出、混音长度与影片终点的关系必须明确。

Player 试听和 FFmpeg 混音应解释同一份事件、源裁切与增益包络；无效果等价实现时应报差异，不能假定预览声音等于成片。检查解码/编码延迟、起始偏移、削波、循环接缝和长时漂移，导出后重新测量实际音画同步。

## Player 行为

- 支持播放/暂停、进度拖动、前后逐帧、回到起点及音频试听。暂停和 seek 时停止旧音频事件，恢复时从目标位置重新调度。
- 实时播放使用单一主时钟并明确音频时钟与帧时钟的映射；后台节流或掉帧不能累积改变影片时长。暂停后的逐帧定位仍须准确。
- 用户未要求时不自动打开浏览器或展示服务地址。内部检查可后台运行；服务启动不等于用户已经看到预览。
- Player 只提供观看与检查，不增加编辑轨道、拖拽改版、素材管理平台或发布功能。

## 导出行为与运行验收

用户满意并明确要求导出后，才进入 MP4 分支；请求预览或泛称“制作视频”不自动触发导出。内部审查用后台 Player、关键帧与音频证据完成，不以 QA 为由自动输出整片 MP4。

renderer 按 `0…N-1` 顺序采集恰好 N 帧，通过资源/React/媒体就绪握手后再编码；按相同音频时间线混音并封装。输出尺寸、fps、时长、编码、像素格式、色彩、音频采样率和声道应写入导出记录。

实现验收至少验证：首末帧与帧数正确；乱序和连续取帧一致；字体图片完整；转场无缺帧；视频源取帧准确；暂停/seek 后声音正确；预览与导出关键帧对应；成片无削波、系统偏移或随时长增长的音画漂移。具体检查和放行规则见 [review.md](review.md)。
