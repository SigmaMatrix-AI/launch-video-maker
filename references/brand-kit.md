# 当前影片工程的 brand kit

`brand-kit/` 只在每次生成的影片工程中创建，**不放在 skill 源码根目录**。它保存本次制作所需的品牌依据和素材，不承担跨工程搜索、同步或品牌资产管理平台职责。

## 收集与组织

产品理解阶段先建立目录和来源记录，素材采集阶段补齐。可按内容使用 `logos/`、`fonts/`、`guidelines/` 等子目录；不必为不存在的素材预建空层级。推荐用 `brand-kit/sources.md` 记录依据，用 `brand-kit/brand.md` 汇总本片采用的品牌规则，名称可调整。

记录应能回答：

| 信息 | 用途 |
| --- | --- |
| 素材标识和工程相对路径 | 定位 Logo、字体、规范或派生资源 |
| 来源 URL、用户文件或源码位置 | 可追溯依据，不把来源路径当运行依赖 |
| 获取日期、版本或内容标识 | 判断素材是否对应当前产品 |
| 依据类别 | 区分用户明确指定、官方规范、产品观察、Agent 推断 |
| 使用条件与状态 | 记录已有授权/许可依据、未知项和替代安排，不凭“下载成功”推断可用性 |
| 用途、变体及加工 | 明暗背景版本、裁切/重绘/格式转换、使用场景 |

Logo、字体文件与可保存的规范随工程保存。规范只能外部查阅时，记录链接和本片采用的规则；来源网页不能变成渲染时必须在线读取的数据源。

## 规则与推断

明确规范写成约束，Agent 从页面观察推导的颜色、字体或动效偏好写成推断并附依据。不得把推断改写成品牌官方要求。

用户要求和明确品牌规范优先于 style 与模板。两项明确要求互相冲突且无法兼容时才请求澄清；缺少正式手册时，可根据产品实际表现作出有依据的选择。

缺少 Logo 或字体时记录缺口和采用的替代方案；不伪造官方素材。任何替代都应在视觉方向与审查中可见。音乐和普通截图通常归入 `assets/` 并记录来源，品牌专属声音或产品品牌依据可纳入 brand kit，避免同一文件重复保存。

## 在制作中的使用

| 阶段 | 具体作用 |
| --- | --- |
| 产品理解 | 建立品牌素材清单、规范和推断边界 |
| 选择 style 与模板 | 判断适配与冲突，明确参考实现需要改造的部分 |
| 分镜编排 | 决定品牌露出位置、Logo 变体、文字层级和动作气质 |
| 素材采集 | 补齐清晰文件，复用已有素材，更新来源和状态 |
| React 实现 | 引用工程内 Logo、字体等文件，将选定品牌值落实到代码 |
| 声音编排 | 对照品牌调性和已有声音规范选择、混合 BGM/SFX |
| 审查与导出 | 核对真实加载的素材、品牌一致性及输出中的清晰度与颜色表现 |

## 引用与审查

从工程资源解析规则引用本地文件，保证 Player 与 renderer 使用同一份素材。若构建工具要求复制到服务目录，记录该副本对应的原文件，避免维护两套品牌真相。

审查必须确认 Logo 比例、留白与背景适配；字体实际加载且字形/字重正确；品牌色和明确规则没有被 style 覆盖；引用路径完整；素材加工及替代有记录。导出后还需检查压缩、色彩转换、放大和字体渲染对实际成片的影响，不能仅检查 brand kit 文件存在。
