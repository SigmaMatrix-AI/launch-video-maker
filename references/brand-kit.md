# 当前影片工程的轻量品牌资源

`brand-kit/` 是本片的资源目录，只在生成的影片工程内创建，不放在 skill 根目录，也不承担跨工程品牌管理。品牌整理服务产品表达，不单独主导镜头、布局和动效。

## 默认只收集 Logo 与主题色

产品理解时保存一个可用的官方 Logo，记录主题色及来源。简短记录可合并在 `brand-kit/sources.md` 或 `sources.json`；没有额外规范就不必创建品牌手册、字体清单或空子目录。

记录 Logo 的工程相对路径、来源 URL/用户文件、获取日期及必要的使用依据；颜色写明是用户指定、官方明确规范还是页面观察。不要把观察到的颜色扩写成官方品牌规定，也不要仅凭下载成功推断使用权限。

明确的用户要求和已有品牌规范仍须遵守。只有任务确实需要时才补充 Logo 变体、指定字体或规范文件；缺少正式手册不构成阻塞。无法取得 Logo 时如实说明采用的文字署名等替代，不伪造官方标识。

## 与 style 的关系

Logo 作为资源按原比例、原色与合适留白展示。主题色作为后续 style 的一个输入，默认用于少量强调、关键控件或品牌露出；不要因为有主题色就让全片背景、文字、插图和案例都变成同一颜色。

背景、正文与辅助色依据所选 style 和画面内容确定；字体也由 style 决定，除非用户或明确规范另有要求。品牌色的使用范围记录在方向中，无需规定统一占比。

真实产品截图和官网案例保存于 `assets/`，保持其原始配色与内容，不能为统一品牌色对整张图重新着色。品牌记录不能代替用途、受众、核心卖点和必须展示功能的分析。

## 流程落点与检查

- 产品理解：收集 Logo、主题色及简短来源，同时采集产品证据和真实画面。
- 方向选择：将主题色克制地融入 style，确定少量强调用途；参考影片继续负责镜头结构。
- 实现：从工程内引用 Logo；使用 direction 中已确定的配色，不在每个场景重新推导品牌视觉。
- 审查：核对 Logo 比例/清晰度、明确规范、颜色主次、真实素材原貌及资源路径。品牌色贯穿不等于品牌一致，不能以“用了品牌绿”作为风格通过的理由。

预览与导出引用同一份本地资源；来源网页不作为运行依赖。产品素材的采集、功能证据和缺口处理见 [pipeline.md](pipeline.md)，画面质量判断见 [review.md](review.md)。
