# 动态表达：时间、注意力与文字

在第三步读本页，按已确认内容选择方法。第一步只描述动态气质，第二步只确认文案、顺序和重点；案例不是额外审批，也不是要求每支片集齐的效果清单。质量问题仍用 [E01–E10](eval.md) 记录。

## 先安排时间，再挑曲线

| 尺度 | Good | Bad | 制作决定 |
| --- | --- | --- | --- |
| 动作 | 点击短促，面板展开舒展，结果准确落定 | 所有对象统一匀速或同款快速滑入 | 对象如何启动、推进、减速/落定？ |
| 镜头 | 输入、操作、结果依次交接，关键内容获得阅读空间 | 上一个阅读任务未结束，新焦点已经进入 | 哪个落点之后观众能开始理解？ |
| 全片 | 紧凑操作之后展开成果，结尾收住 | 全片同速，或所有镜头一起变慢 | 重点在哪，哪些过程可以压缩？ |

呼吸感包含时间分配、速度变化和注意力释放。快速动作可以有力；匀速扫描、稳定移动也有用途；同一种曲线本身不是缺陷。判断实际效果，避免用全局降速或给所有物体加弹簧代替编排。

重点段落在 `storyboard.md` 简记：**节奏意图、关键落点、阅读窗口、下一镜承接**。例如“操作紧凑，结果舒展；摘要展开完成是落点；关键要点清晰后留出理解时间；同一结果进入分享”。这是制作说明，不要求每镜填表，也不强制固定进入/停留/退出比例。

可读时间看关键信息何时清楚呈现，不能从第一字入场就算全句可读；字数、字号、画幅与视觉干扰都会改变需要的时间。主体完全停住是有效选择，背景不必持续漂浮。有声任务结合乐句和可听落点；无声案例只支持视觉判断。

## 文字先确定表达目的

先选句意、重点词和语义分组，再决定动作与下一镜的关系。中文优先按短语分组，品牌词、数字单位和标点保持含义。一个文字镜头通常只需一种主要方法；全片保持气质一致，关键揭晓再增加强度。

| 案例 | 适合表达 | Good / Bad | 可调整项 / 边界 |
| --- | --- | --- | --- |
| [R01 节奏](../examples/motion-language/src/rhythm.tsx) | 操作后需要读懂结果 | 短动作→舒展结果→阅读 / 等长段落、结果迟到后匆忙切走 | 调整动作和阅读分配；不要把示例秒数当通用标准 |
| [T01 语义揭示](../examples/motion-language/src/text-reveal.tsx) | 一句话逐层建立意思 | 按“把复杂的资料，/变成/清晰的重点”推进 / 每字同节奏弹跳 | 分组、组间间隔、位移、重点词；不适合让长段落逐字等候 |
| [T02 关键词替换](../examples/motion-language/src/text-replace.tsx) | 一个句式表达多种选择 | 保留“把想法变成”，替换文档/演示作品/作品 / 每次整句重来 | 有限词序列、宽度、切换与阅读时间；没有变化含义就不强用 |
| [T03 重点聚焦](../examples/motion-language/src/text-focus.tsx) | 需要从铺垫落到一个重点 | 焦点有方向，最终停在结果 / 不断循环改变焦点 | 清晰度、强调和最终落点；文字定格后要可读，模糊不掩盖低清 |
| [T04 文字进入产品](../examples/motion-language/src/text-handoff.tsx) | 文案中的对象能自然成为产品输入或结果 | 同一“发布计划”进入搜索框 / 标题清空后 UI 独立滑入 | 对象位置、尺寸、容器显现与结果时序；不能为了衔接虚构能力 |

T01–T03 的表达原理可参考 React Bits 官方 [Split Text](https://reactbits.dev/text-animations/split-text)、[Rotating Text](https://reactbits.dev/text-animations/rotating-text)、[True Focus](https://reactbits.dev/text-animations/true-focus)。本地实现未复制其代码，使用当前帧计算；网页的滚动、指针或墙钟触发不能直接成为视频的时间源。

## 只运行需要的对照

从仓库根目录，在已有依赖和 build 后运行：

```bash
npx tsx examples/motion-language/create-study.ts films/t01-good --case T01 --variant good
cd films/t01-good
npm ci
npm run preview -- --open
```

另一版使用新目录和 `--variant bad`。完整入口与资产说明见 [案例说明](../examples/motion-language/README.md)。生成工程包含可编辑源码和本地资产；不要为套方法重建用户全片。修改文字时检查字体字形覆盖。

每对同文案、顺序、字体、素材、画幅、总时长和无声条件，变量是该方法的时间或表达。案例是虚构方法演示，`good` 是设计意图标签，不是“显得很贵”的认证。Bad 不是对参考原片的评价。当前实际检查范围见 [验证记录](../docs/validation/research-motion-language-results.md)。

## 看、修、复看

正常速度看是否来得及读、知道该看哪里、记住哪个变化；静帧看布局，连续窗口看文字交叠、裁切、落定与衔接。只看到静帧或技术播放日志时，保留节奏感知未验证。参考片中精确停顿、缓动和声音需要重新连续观察，不能由旧抽帧推出。

局部问题用“区间＋现象＋E 编号/方法 ID＋修改动作＋复看条件”，例如：`4.1–5.0s / 替换词还未读清又切换 / E09/T02 / 保留句子主体并延后下一词 / 正常播放能读完每个关键词`。修改当前片段及两侧接缝，有声音则同步复核混音；交付前完整复看。模板严格复刻时先遵守约定范围。
