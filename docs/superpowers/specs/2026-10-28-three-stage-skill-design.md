# 自主设计三步走：设计约定

状态：已按此约定实施于独立 worktree；验证范围见 [验证记录](../../validation/three-stage-skill-results.md)。尚未切换安装或发布。

## 目标与已确认方向

解决整片制作消耗大量 token 后仍不满意、成片像 PPT 的问题。把自主设计拆为：

1. **定调性**：同一代表内容给出 3 种不同视觉效果图，由用户选择方向。
2. **定故事**：给出故事脚本和简易草稿分镜，确认视频讲什么。
3. **做质感**：在已确认的故事和方向上打磨 UI、镜头衔接、节奏、动效和声音，直到达到认可的品质。

第二步不是动态验证或质感验收。允许低保真画面、占位素材和粗略时长，不要求最终 UI、逐帧时序、转场或音乐卡点。第三步可以先打磨一个代表段落再扩展全片，但这是阶段内部策略，不增加用户必须确认的第四个关卡。

用户新增的默认创作准则：**Good：标题和文字单独镜头出现，并有高亮词或动效；Bad：标题和配图左右构图、上下构图，像 PPT。** 此准则针对自主设计的宣传表达；真实产品 UI 内的标题、标签不因此被删除。明确要求保留编排的模板复刻遵循用户指定范围。

成功标准：用户能分别判断调性、故事、制作质感；失败尽早暴露；修改能定位到镜头与具体问题。节省 token 和提升喜好度是目标，未做对照实验前不声称具体节省比例或必然达到参考质量。

## 讨论过的路线与选择

- 原流程连续做完整动态草稿再审阅：自主性强，但方向与内容错误发现过晚。
- 第二步提前做动态小样：能暴露运动问题，但用户明确指出第二步要确认的是故事脚本。
- **选择三步走**：先选视觉、再确认故事、第三步集中制作与打磨。保留两个创作决策点，减少重复确认；已确认要求持续有效。

只在 Agent 自规划路线启用新的默认流程。模板 reference 路线保留已有复刻范围与编排，不强制追加三方向竞稿；只修跨文档冲突。

## 三阶段契约

| 阶段 | 输入与产物 | 用户确认点 | 本阶段不承担的工作 |
| --- | --- | --- | --- |
| 1 定调性 | 最小只读产品研究；`records/brief.md`；同一关键内容的 A/B/C 效果图；`records/direction.md` 记录差异、素材来源、可实现性和选择 | 用户选方向或明确授权代选；三个都不满意则针对反馈重做候选 | 三套完整影片、三套完整分镜、精细运动系统 |
| 2 定故事 | 已选方向；`records/script.md` 讲清开头、问题、产品介入、结果、记忆点/CTA；`records/storyboard.md` 用简图或画面说明对应故事段落 | 用户确认内容、顺序和必展示项；已给定且确认的脚本直接复用 | UI 精修、镜头衔接验收、精确帧区间、动态样片必交 |
| 3 做质感 | 将已确认分镜扩为制作分镜，加入动作、焦点、镜头衔接、时序与声音；实现可播放作品，按案例诊断修改 | 持续吸收反馈；交付前确认是否满意，不逐条申请技术修改许可 | 擅自重写已确认故事、自动把视觉范围通过说成完整视听通过 |

三个方向须在排版、视觉语言、材质或空间组织上有实质差异，不能只换配色，也不能换故事内容制造差异。效果图应尽量使用可获得的产品素材，说明无法兑现的资产风险。生成方法按已有工具能力选择，无需为阶段一新增专用渲染器。

`records/direction.md` 包含候选、选择、当前版本以及用户确认依据；`records/script.md` 包含内容版本与确认依据；`records/storyboard.md` 保留内容段落 ID，第三步补充制作信息而非覆盖已确认脚本。记录确认原话或明确的用户指令，不伪造时间、批准或默认选择。

续作先读取记录和当前用户反馈。单镜头视觉反馈留在第三步；内容改动只回到受影响的第二步；整体调性变化才回第一步。没有回复不是批准。用户明确说“你决定、直接做完”时，在授权范围代选并记录，不重复要求确认。

## 以案例为入口的质量标尺

`references/eval.md` 首屏是 Good / Bad 对照。每个案例都有稳定 ID、表达目标、Bad、Good、判断关键、参考证据或“建议示例”标记。案例用于理解原理，不要求每条影片套同一招式。下表是最小内容集：

| ID | 主题 | Good | Bad | 判断关键 |
| --- | --- | --- | --- | --- |
| E01 | 主体动作 | 卡片被选择、内容被编辑、素材进入作品 | 主体不变，背景光晕或截图持续缩放 | 动作是否带来新信息？ |
| E02 | 跨镜头承接 | 上一镜选中对象成为下一镜主角 | 每镜清空再生成另一套元素 | 能否认出前后对象的关系？ |
| E03 | 注意力 | 输入→操作→结果逐次交接焦点 | 标题、UI、光标、背景同时抢动 | 此刻该看哪里是否明确？ |
| E04 | UI 呈现 | 放大当前任务区域并保留必要上下文 | 整张后台截图配小字介绍 | 不暂停能否理解关键操作？ |
| E05 | 镜头用途 | 推近看操作、拉远看结果与上下文 | 所有内容一律旋转、倾斜、推拉 | 镜头运动揭示了什么？ |
| E06 | 动作质感 | 起动、推进、落定有区别，按元素角色设计 | 所有元素同款滑入/弹簧，落定后还抖 | 动作能否准确结束并让结果可读？ |
| E07 | 节奏 | 次要操作压缩，关键变化完整，结果可读 | 等长换页，或一直快切没有落点 | 重要内容是否获得足够时间？ |
| E08 | 视觉强调 | 最强变化留给核心结果 | 每个元素都是一次高潮 | 能否记住关键揭晓？ |
| E09 | 停留 | 结果和 CTA 稳定展示 | 为动而动，文字一直漂浮 | 静止是否帮助理解与记忆？ |
| E10 | 文字独立成镜 | 标题和文字单独镜头出现，并有高亮词或动效 | 标题和配图左右构图、上下构图，像 PPT | 文字是否有自己的视觉表达，而非解说配图？ |

E10 的具体好例：先用独立文字镜头呈现“一份内容，多种语言”，依语义强调“一份 / 多种”，再进入产品演示。避免靠重复背景装饰替代文字设计；也不要求每个词都跳动。它是用户新增要求，不冒充来自参考片的已验证结论。

## 第三步迭代与成本控制

每轮记录：时间区间、可观察问题、案例 ID、修改动作、复看条件。先修故事表达执行错误、PPT 式展示、注意力冲突，再修动作和材质细节。每轮选择最影响观感的问题，复看当前段和前后接缝；修改时序后复核混音。例：素材选中后直接切页导致对象关系中断，参考 E02，让它保持可辨认地进入画布。

代表段落优先是建议策略，不是新审批。避免同时制作三套影片、每轮全片重写、重复读取全部参考。能获得真实用量时记录阶段用量；不能获得时仅记录制作/重做次数，不能编造 token 数据。质量停滞时说明仍不满意的具体差距并请求针对性反馈，不能无限自主循环或以评分代替用户满意。

配乐的强度按已选方向和故事服务：保留现有高能量偏好作为默认候选，不将快节奏或每拍切镜等同于高级。这是本计划建议的组织方式，不是两条参考已试听得出的事实。

## 验证与完成定义

实施需验证：未选方向不展开全片；第二步只确认故事；明确授权代选可继续；第三步局部反馈不重开全部流程；模板复刻不被新流程强行改编；文字独立镜头要求能落入实际输出；缺视听证据不虚报通过。

文档链接和记录路径检查只能证明接口一致。行为验证需要代理场景记录；视觉验证需要在第三步用新主题的短片段展示文字独立成镜和主体连续变化，再与 Bad 对照检查。未完成实测时不得宣称新版 skill 已提升成片质量或节省 token。
