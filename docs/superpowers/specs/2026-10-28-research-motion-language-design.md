## 1. 问题与目标

用户运行两个 demo 后反馈：官网探索停留在首屏；动画缺少速度与时间分配的变化、缺少呼吸与节奏（后续反馈澄清为“匀速”，不是否定快速动作）；独立文字镜头有效，但表达方式没有充分发挥。本轮希望让 Agent 在制作前获得足够依据，在制作中有具体的选择方法，并通过实际播放验证效果，减少整片完成后的盲目返工。

三个问题属于同一条制作链：官网研究提供内容与素材 → 故事决定讲什么 → 第三步安排时间、注意力和文字表达 → eval 定位具体差距。继续采用三阶段，不增加用户审批阶段。

成功标准：

- 研究能发现首屏之外与选题有关的内容，明确素材、证据和缺口。
- 功能巡礼、单功能发布、成果展示、贯穿案例均可成为合理脚本，不强迫复杂故事。
- 第三步能安排不同层次的动作速度、阅读停留和段落轻重。
- 文字动效与语义、重点和下一镜有关，中文优先按语义分组。
- 新增规则能在真实制作行为和可播放片段中被观察；不以文档齐全、技术测试或自评分证明审美提升。

## 3. Approaches 与本轮选择

| 方案 | 收益 | 代价 / 局限 |
| --- | --- | --- |
| 只补流程与文字规则 | 改动少，容易维护 | Agent 仍可能理解原则但生成相同的快速滑入；动态效果缺少共同参照 |
| 流程补强＋少量可运行 Good / Bad 案例 | 研究、制作选择和评审可相互对应；实现片段可复用 | 需要制作、观看案例，并用真实 demo 验证迁移效果 |

本 spec 采用第二种。用户在方案讨论后要求落 spec 和 plan；具体实现数量、文件划分和实验安排属于下文标明的设计决定，不冒充用户逐项指定。

本轮不建设通用动画组件平台、不引入自动抓取全站系统、不新增自动审美分数、不引入 React Bits 全量依赖。模板原有编排与 runtime 核心保持当前职责。

## 4. 全局约束

- 保持“3 张效果图定调性 → 脚本与粗分镜定内容 → UI、衔接、节奏、动效与声音做质感”。
- 第二步不要求动态样片、最终 UI、精确帧区间、音乐卡点或节奏验收。
- 功能名称可以组织分镜；同一案例贯穿是可选方法，核心展示的事实与素材需要依据。
- 用户明确代选/代定授权持续有效；沉默不是批准；局部修改不重开无关阶段。
- 模板 reference 遵守已约定的构图、动作和时序；研究方法可共用，新文字方法不强制覆盖模板。
- 沿用 React + TypeScript、统一帧控制、Playwright、FFmpeg 和 Node.js 24+；不新增运行时依赖或修改 runtime 公共 API、review schema 与七维门槛。
- 画面由当前帧、输入、素材与固定种子确定；顺播、倒退和乱序 seek 到同一帧应得到同一画面。
- 默认交付本地预览；用户明确要求导出后才生成用户影片 MP4。
- 保留真实素材来源、能力与状态含义；官方文案陈述、实际观察和创作推断分开记录。
- 不以静帧、播放日志、文档检查或评分代替连续观看与试听；缺少证据时保留未验证状态。
- 保留既存 `SKILL.md` 对照组名称改动，不修改原工作目录、安装链接或历史规划快照。

## 6. 官网探索：先全貌，后按选题深挖

### 6.1 浏览策略

1. 阅读首页主要内容区、导航和产品入口；滚动到后续区块，查看影响理解的 tab、轮播或折叠内容。实际浏览、静态截图和页面文本各自证明不同的事情。
2. 建立候选内容与素材清单，再打开与候选相关的功能、案例、文档或官方演示页面。优先回答会改变选题或画面的问题，不机械逐页遍历。
3. 区分产品能力说明与可见状态：营销文案可支持“官方这样介绍”，无法单凭它推断真实操作细节或性能。未观察的交互保留缺口；必要时选有依据的结果展示或标明示意。
4. 选中内容后，只补它需要的截图、录屏、状态和清晰度。复用已有效的研究；没有网站或用户限定只用提供素材时，按现有材料工作，不强制上网。

### 6.2 最小产物与停止条件

在 `brief.md` 记录受众、候选主题、品牌要求及简短依据表：

| 内容 / 用途 | 来源页面或本地材料 | 证据性质与观察到的内容 | 可拍素材 / 状态 | 缺口 |
| --- | --- | --- | --- | --- |
| 搜索 | 真实 URL 或文件路径 | 官方说明 / 已观察演示 / 推断分别标明 | 输入、结果、高亮等实际可用内容 | 待补的状态或清晰度 |

上表是字段示例，不证明任何具体产品支持搜索。复杂研究可拆为 `records/research.md`，brief 只保留结论和链接；默认不增加必填文件。资产落在影片工程内，保存来源、必要的采集状态与时间；不将整个网站文本反复灌入上下文。

完成条件：已了解主要相关能力与素材分布；选中内容有可定位依据；关键表达有可用素材或明确替代方案；未解决问题不会迫使 Agent 发明功能或改变已选主线。没有固定页数指标。

登录受限、页面错误或关键素材不可达时，记录已覆盖和未覆盖范围，使用现有材料推进可独立完成的部分。涉及核心事实的缺口不得由猜测填补。停止反复访问同一失败入口。

## 7. 呼吸感：三个尺度的时间编排

| 尺度 | 要做的选择 | Good | Bad |
| --- | --- | --- | --- |
| 动作 | 启动、推进、落定怎样体现对象角色 | 点击短促，面板舒展，结果稳定 | 所有对象同款快速缓动 |
| 镜头 | 注意力何时交接，关键内容何时可读 | 主要动作完成后给结果阅读空间 | 上一阅读任务未结束就引入下一焦点 |
| 全片 | 哪些段落压缩，哪些段落展开或收束 | 紧凑操作、成果展示与结尾有不同重量 | 等长换页，或整片统一减速 |

第三步为需要编排的重点段落补四项简记：节奏意图、关键落点、有效阅读窗口、下一镜承接。记录可以是一段话，不强制为每个镜头填写同一表格。

例如：`前段紧凑，结果舒展；摘要完成展开是落点；关键摘要清晰后留出理解时间；分享对象接入下一镜。` 示例不是某个产品的事实。

阅读窗口依据实际文字量、画幅和焦点判断，不能从第一字开始入场就算整句可读，也不固定所有标题停留同样秒数。关键文字的清晰和稳定是观察重点，不禁止可读的移动文字。

静止、硬切、淡入、克制的背景运动都可以成立。不得把呼吸感等同于持续漂浮、全局降速或每段固定“进入—停留—退出”。有声音时同时编排乐句、落点与尾音；无声示例只证明视觉节奏。

## 8. 文字动效：按表达目的选择

| ID | 目的与方法 | Good | Bad | 关联 eval |
| --- | --- | --- | --- | --- |
| T01 | 语义分组揭示 | 短语依次建立句意，重点词落定可读 | 每个汉字机械等间隔弹跳 | E03/E06/E10 |
| T02 | 关键词替换 | 保留句子主体，有限次替换承担变化的词 | 整句话持续轮换，阅读任务被反复重置 | E03/E07/E09/E10 |
| T03 | 重点聚焦 | 清晰度或强调沿语义移动，最终停在重点 | 焦点无限循环，最后仍不知道要记住什么 | E03/E09/E10 |
| T04 | 文字进入产品 | 文案中的对象变成输入或结果，承接下一镜 | 标题清空后另一张截图独立滑入 | E01/E02/E10 |
| R01 | 动作与阅读的时间分配 | 快动作与舒展结果交替，同样时长内留出理解 | 相同内容按等长段落快速入场、抢读 | E03/E06/E07/E09 |

第一批选 5 组案例是本设计的范围决定，不要求一支影片使用全部方法，也不要求固定文字镜头数量。T01–T03 可借鉴 React Bits 的表达原理；T04 是跨镜头编排案例，并不声称是其现成组件。

每张案例卡包含：表达目的、Good / Bad 现象、运行入口、可调整项、阅读与衔接说明、不适用条件、来源与实际观察范围。创作时先读短索引，仅在选中方法后读取相关实现。

中文默认手工确认语义分组；英文、数字、单位和品牌词按含义组合。标点不孤立弹出；品牌或真实 UI 标签不被拆错。全片选择与方向一致的少量方法，重点段落才使用更强变化。

React Bits 参考：

- [Split Text](https://reactbits.dev/text-animations/split-text)：字符或词的错时进入。
- [Rotating Text](https://reactbits.dev/text-animations/rotating-text)：短语轮换。
- [True Focus](https://reactbits.dev/text-animations/true-focus)：词语间的清晰度变化。

这些页面已读到官方说明，尚不代表逐一观察了交互预览或验证其代码可直接用于影片。优先用现有帧体系实现所需原理；如借用源码，先核对实际许可证与依赖并记录来源，不依赖滚动、指针、定时器或墙钟触发。

## 9. 案例工程与参考片

新增 `examples/motion-language/`，定位为局部方法案例，与正式影片模板及 runtime 验证片区分。追踪案例源码、短说明和必要的可分发资产；生成项目、依赖、截图和审阅包放 ignored 的 `films/`。

运行入口：`npx tsx examples/motion-language/create-study.ts <新目录> --case R01 --variant good`，支持 R01/T01–T04 和 good/bad。生成器复用 `initProject(target)`，复制选中案例所需源码、配置与资产。拒绝覆盖已存在目录；不自动预览、导出或修改模板。随后按生成工程的现有命令安装、prepare、preview。

每组 Good / Bad 使用相同文案、内容顺序、字体、画幅、素材、总时长和声音条件，仅改变该案例对应的时间或表达方法。案例默认为 1920×1080、30 fps、无声、约 6–10 秒；这属于实验规格，不约束用户影片。Bad 也必须可播放、文字正确，不以破损资源制造优势。

每个案例暴露当前帧的 React 画面与 Film 元数据；不建立通用动画 DSL。使用已核实来源与字形覆盖的字体，生成工程复制依赖资产，不能运行时回读用户 Downloads 或其他工程。无需随仓库分发参考原片。

## 11. 验证、成本与完成边界

分开验收：

1. **行为：** 使用相同输入对照旧版与新版；观察实际浏览和制作选择，不能只问 Agent 是否同意规则。用小型本地网站夹具验证首屏外、交互区和相关子页发现；不把夹具源码交给受测 Agent。
2. **技术：** 对新案例做随机/逆序取帧一致性、落定后文字状态、实际字体/遮罩与生成工程独立运行检查。测试只证明对应技术性质。
3. **感知：** 同内容的 Good / Bad 正常速度播放，记录阅读、注意力和承接的具体差异；不能因为名称叫 good 就预判更好。
4. **真实迁移：** 找到用户的两个 demo 后保留原版，选择代表段落进行局部对照。官网研究实验与固定脚本的节奏/文字实验分开，最后再看组合效果。未找到 demo 时先完成前面三类，真实迁移保持待验证，不换用旧示意片冒充。

正文、分镜与素材只保存可复用的简短结论；按阶段加载研究或动态指南；案例只运行需要的一组。每轮优先修最影响理解/观感的问题，只复看受影响段落及接缝，交付前完整复看。有声音且时序改变时复查实际混音。连续一轮针对性修改没有改善时，记录具体分歧并寻求针对性反馈，不无限加动效。

记录实际 token 数据（若能取得），否则记录浏览、生成、返工次数和耗时，不估算节省比例。

交付状态分开写：规则/案例已实现；行为和技术检查结果；感知观察范围；两个真实 demo 对照结果。真实迁移未完成时不能报告三个品质问题已解决。实现、安装路径切换、额外发布和远端推送不属于本次仅落文档的动作。
