## 可复现技术验证

前提：按 README 安装 Node、FFmpeg、Chromium，先构建运行时。

```bash
npm run build
npm test
npm run test:long
```

本机环境：macOS arm64、Node 24.17.0、npm 11.13.0、FFmpeg/ffprobe 8.1.2、Playwright 1.64.1、Chromium revision 1248 / 156.0.8078.4。npm 包和 Chromium 固定版本；FFmpeg 是外部工具，由 doctor/导出记录保存版本。

| 检查 | 结果与证据范围 |
| --- | --- |
| TypeScript 构建 | 通过 |
| 默认套件 | 70 项：69 通过、0 失败、1 跳过（显式开启的长片测试） |
| 60 秒编码同步 | 单独运行 1/1 通过；1800 帧，已知视觉闪帧与音频脉冲在起、中、尾位置的误差不超过一帧 |

默认套件串行执行测试文件，避免 npm 安装、FFmpeg 与浏览器互相争抢资源。调试时发现无头浏览器音频设备启动时延可变：墙钟 1.1 秒不等于已输出 1.1 秒声音。因此播放测试核对真实设备时间戳及音源启动次数，不使用墙钟帧数冒充音画同步。编码同步另有独立的已知信号测试。

长片测试在最终视频预取变更前通过；随后变更仅涉及 VideoFrame 图片预取与缓存，长片探针不含视频素材。该变更经过新增视频测试和完整默认套件验证，没有无依据地把它写成重跑过长片测试。

## 风格与产品工程

本机交付位置为仓库平级 `launch-video-maker-output/2026-10-26/`。每个工程包含独立 runtime 包、锁文件、源码、本地素材、brand kit、制作记录和 `.lvm/review/` 证据。生成内容不提交到 skill 仓库。

| 工程 | 内容 | 审查状态 |
| --- | --- | --- |
| `styles/dark-keynote/` | 12 秒、24 fps；单一强调色、暗网格、数字滚动与停留 | 修复高光矩形、强调色分散；已观察静帧及后台完整播放状态，未完成连续视听 |
| `styles/living-screencast/` | 12 秒、30 fps；忠实重绘 runtime 控件、DOM 锚点、像素角色与跟随镜头 | 修复时间码裁切和字幕重叠；未完成连续视听 |
| `tapvid/` | 24 秒、1080p30；依据用户确认的 tapvid.ai，包含输入、编辑、Brand Kit、CTA | 官方主张、Logo/字体/插图来源已核对；独立后台播放遍历 720 帧，无错误；未通过商业审查 |

两个用户初始 style 仅作为文档与资源输入：demo 没有当作模板运行，也没有修复或移植其原依赖。两片为新叙事、新源码。未提供配音，因此不声称完成语音制作或字级同步验证。

TapVid 使用官网公开营销插图，并在记录中说明它们不是已认证的实际产品操作画面。没有编造性能、客户、价格承诺，没有调用收费生成或发布。当前设计建议仍包括：让“素材→作品”或“修改前→修改后”更具体可见，强化品牌元素传递和动态记忆点。

独立 reviewer 的能力边界：可检查截图、相邻帧、后台播放状态和音频数据，不能实际听音或直接连续观察实时流。因此七维保持未评分，不能通过 ≥7.5 门槛。三个工程的 `independent-review.md` 保存详细观察与限制；`review.json` 保持 incomplete。

测量响度：Dark Keynote −14.2 LUFS / −2.9 dBTP，Living Screencast −14.0 LUFS / −1.5 dBTP，TapVid −19.8 LUFS / −5.9 dBTP。这些是数据而非听感结论。TapVid 需结合试听确定响度目标，不能简单加增益到接近满幅。

最终 runtime 补充视频预取后，三个工程均重新安装包并核对源码摘要、重新生成关键帧和混音证据；未改影片内容，三片也均没有 VideoFrame 输入。独立报告保留其原审查版本，另附封装更新记录，不把制作方复测冒充新的独立商业通过。

## 已采用的实现取舍与后续工作

- 视频先完整解码导入片段，默认总预算 2 GiB；建议先裁切长录屏。片段级解码优化留待后续。
- 每次采集前后重新校验项目摘要，优先防止新旧版本混用；大型素材工程的摘要性能仍可优化。
- 生成工程使用 npm 脚本名 `prepare`，普通安装会触发生命周期；只安装依赖时使用 `npm ci --ignore-scripts` 再显式准备。后续可重命名用户命令以消除隐式准备。
- setup 安装固定 Chromium，不自动安装系统 FFmpeg。其他操作系统未验收。
- 浏览器原生缓存和解码器由浏览器管理；六句柄限制针对 runtime 持有的推测图片，不是整页内存硬上限。
- 继续商业验收需要具备实际连续观看和听音能力的独立评测者，并完成 TapVid 的设计修整与响度决策。用户要求导出后，仍需审查实际 MP4，不能沿用预览工程结论替代。

## 用户实播反馈后的预览修复

用户实际播放发现严重闪烁和版本错误。此前“帧状态可遍历”的检查不足以证明显示稳定，本次增加实际像素回归，不沿用旧测试结论掩盖问题。

- 根因一：macOS 的 `.DS_Store` 进入项目摘要，同时任意文件监听事件会永久标记版本变化。现在排除操作系统元数据，以实际内容摘要判断；同内容文件 touch 不失效，真正源码修改仍失效。
- 根因二：准备帧仅用 `visibility:hidden`，场景子元素可用 `visibility:visible` 覆盖，导致未就绪帧提前叠上当前画面。现在对整个准备层使用 opacity 隔离，同时保留隐藏与无交互状态，全部就绪后再切换。
- 预览界面补齐居中画布、自适应缩放、明确的控制区；缩放不改变导出画面。播放器 CSS 限定在自身界面，防止隐藏或改写场景中的语义元素。
- 四项新增回归均先在旧实现失败，再在修复后通过：元数据/touch、显式可见子元素的待就绪像素、窗口缩放，以及预览/采集中的语义内容一致性。
- TapVid 实际 24 秒后台播放到第 719 帧并自动停止；120 次 Logo 区域像素采样一致，页面错误为空，静态资源仅六次请求，音源仅启动一次。该结果验证显示稳定性与播放行为，不替代商业听审。

## 评测体系 v2 验证

本轮实现独立视觉评测的工具与交接流程；完整七维商用门槛保持不变。visual范围可单独通过，但commercialStatus始终incomplete；暂缓听感评测，不安装听音模型，不发送视听内容到外部API。精选BGM/SFX素材另行建设，产品实战等待模板ready。

- 新包采用唯一目录，文件、manifest、源码版本、runtime与实际MP4分别绑定；历史报告不会被覆盖。
- 默认采集概览和场景／marker邻域连续窗口；预算为1200帧、2 GiB，不静默降低覆盖；实际后台播放单独记录，不能冒充连续观看。
- 缺上下文、缺观察能力、旧报告、损坏证据、低分及未解决阻断均有专用门槛测试。复测不能删除旧问题、降低严重程度、只引用历史证据或继承旧评分。
- 已有MP4只读采样，文件变化触发mp4-changed；预览检查不自动产生整片视频。
- 工程迁移后只用vendor包安装并生成、校验证据包；实际源码修复后生成--previous新包，验证评分清空和逐项复测。
- 全套技术测试70项：69通过，1项显式opt-in长片测试跳过。未修改renderer、audio或Player同步逻辑，未重跑60秒同步测试；原记录只代表原运行。
- TypeScript构建、Markdown链接及skill-creator结构验证通过。Python校验使用临时uv环境的PyYAML，没有新增项目依赖。新review模块经Prettier格式化，便于独立审查。

独立代码审查完成，发现并修复两项Important问题：clean曾删除不可重建的手写评测报告／复测历史，现仅清理已知缓存，保留默认、自定义及嵌套评测记录；FPS曾按字符串比较，现用精确有理数比较，60/2与30/1等价。两项均有失败复现和修复后的测试，全套最终70项、69通过、1跳过；无Critical或延后Minor问题。

独立reviewer实际逐张查看了12帧技术fixture，记录静态与完整窗口观察，连续视觉／听音能力均声明不可用；六维保持unverified/null、声音deferred/null，CLI退出2，scopeStatus和commercialStatus均incomplete。该演练针对最终修复前的审查版本；runtime变化后，旧演练包被正确标记runtime-changed，未迁移旧结论充当新版本通过。

技术fixture的合成分数仅用于门槛测试，不是商业影片评价；原有三片商业状态不随工具完成而改变。
