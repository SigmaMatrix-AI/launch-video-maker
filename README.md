# Launch Video Maker

面向 AI Agent 的产品宣传视频制作 skill：从产品理解、视觉设计与分镜编排，到 React 影片实现、声音编排和独立审查，以自主决策完成制作。

项目将**参考模板、style 与品牌素材分离**，让 Agent 根据产品选择叙事与视觉方向，自由改造实现，而不是只替换固定模板中的文案和图片。

## 设计原则

- **自主推进。** Agent 记录关键判断并连续完成制作，不设置逐阶段确认。只有缺少无法合理推断的必要信息时才提问。
- **产品与品牌优先。** 明确的用户要求和品牌规范优先；style 补充设计方向，模板提供实现参考。
- **源码可改造。** 参考模板采用可运行的 React 动画源码，允许增删场景、重排结构，以及修改布局、动效和时长。
- **素材归属影片工程。** 本次使用的品牌依据、截图、录屏与声音素材保存在当前工程中，记录来源并复用。
- **预览与导出一致。** 两者使用同一套场景、素材、帧计算与音频时间线。
- **用实际视听证据验收。** 制作 Agent 自检后，由独立 subagent 评测；静帧和源码检查不能替代动态、声音与成片检查。

## 模板、Style 与 Brand Kit

三者分别回答“如何实现”“呈现什么气质”和“必须遵循哪些品牌依据”。

| 内容 | 存放位置 | 职责 |
| --- | --- | --- |
| 参考模板 | `templates/<template-id>/` | 提供叙事、布局、动画和节奏的 React 实现参考，以 `template.md` 为说明入口 |
| Style | `styles/<style-id>/` | 用 `style.md` 自由描述字体、排版、动效、材质与视觉 tone，可附参考实现和素材 |
| Brand kit | 当前影片工程的 `brand-kit/` | 保存产品 Logo、字体、品牌规范及来源，区分明确要求与 Agent 推断 |

模板与 style 可以交叉组合，由 Agent 理解后落实到源码；不要求每个模板预先支持所有 style，也不要求 style 遵循固定字段或 schema。

没有适用的内置参考时，Agent 根据产品与用户要求自主设计，并记录设计方向。Brand kit 不存放在本仓库根目录，也不承担跨工程品牌管理。

## 制作流程

1. **理解产品，建立 brand kit。** 检查资料、网站或源码，确定受众、核心卖点、用途与制作约束，收集品牌素材并记录依据。
2. **选择 style 与参考模板。** 阅读候选说明，记录借鉴范围与改造方向；没有可用参考时自主设计。
3. **编排分镜与声音方向。** 确定场景顺序、时长、文案、转场与素材需求。需要卡点时，先选择和分析 BGM，再锁定分镜。
4. **采集并整理素材。** 按分镜获取截图、录屏和其他素材，复用已有资源，补齐品牌记录与来源。
5. **实现 React 影片。** 使用 React + TypeScript 编写场景，以统一帧控制驱动画面，逐场景检查关键帧和动态表现。
6. **完成声音编排。** 细化 BGM、音效、裁切、音量和淡入淡出；画面时序改变时同步更新声音时间线。
7. **独立审查与修复。** 自检后交给未参与制作的 subagent，依据评测修复并复测，直至满足交付标准。
8. **按需预览与导出。** 默认完成到通过检查的可预览工程；用户要求时展示预览，用户满意并要求导出后生成 MP4，再验收实际成片。

用户未要求时，不自动打开浏览器或展示本地服务；内部检查可在后台进行。预览请求不自动触发导出，内部审查也不自动生成整片 MP4。

各阶段的输入、动作、产物和返工衔接见 [制作流程](references/pipeline.md)。

## 使用方式

将本仓库放在 Agent 可读取的位置，保留 `SKILL.md` 与 `references/` 的相对目录关系。通过所用 Agent 的 skill 加载机制加载，或明确要求其先阅读 [SKILL.md](SKILL.md)。具体安装路径由宿主工具决定，本项目不提供专用安装器。

制作请求可以包含：产品资料或网站、目标受众、重点卖点、使用场景、目标时长与画幅、已有品牌规范及素材。允许 Agent 推断未明确的创意细节，不必先填写固定表单。

例如：

```text
请使用 launch-video-maker，为这个产品制作一支 30 秒、16:9 的宣传视频。
产品资料和品牌素材位于当前工作区的 product-materials/。
受众是小型设计团队，重点表达从想法到可分享原型的流程。
请自主决定视觉方向、参考模板、分镜与声音方案。
先完成工程与内部审查，暂不打开预览或导出 MP4。
```

这是制作请求示例，不是当前可直接运行的视频演示。运行层实现前，可以开展产品分析、品牌整理、视觉方向和分镜工作；缺少动态验证能力时，工程不能标记为“可预览”或“审查通过”。

## 技术方案

| 技术或组件 | 职责 |
| --- | --- |
| React + TypeScript | 组织场景、布局、文字、素材与动画状态 |
| 统一帧控制 | 根据指定帧计算确定性画面，支持连续播放与任意帧定位 |
| 轻量 Player | 播放、暂停、进度拖动、逐帧查看与音频试听 |
| Playwright | 等待资源、React 更新与媒体目标帧就绪后，逐帧采集 |
| FFmpeg | 编码画面、裁切和混合音频，封装 MP4 |

运行层采用共享时间语义，避免预览与导出各自维护动画或音频时序。资源就绪、取帧握手、视频素材准确定位、音频包络及同步约定详见 [运行契约](references/runtime-contract.md)。

本项目不依赖 Remotion，不提供可视化编辑器、镜头库或镜头选择系统、只能替换素材的硬模板模式、逐阶段共同创作模式、剪映工程导出、发布功能或跨工程品牌管理平台。

## 质量标准

影片以高端商用定制标准验收。独立 subagent 从以下七个维度评分，每项使用 0–10 分制，**全部达到 7.5 分才满足分数条件**：

- 风格还原
- 创意与惊艳
- 动效工艺
- 设计与排版
- 质感与细节
- 声音与同步
- 技术规格

不以平均分抵消低分。必要证据缺失时标记“无法验证”；存在错误产品信息、违反明确品牌要求、关键素材缺失或明显音画错位等阻断问题时，即使分数达标也不能通过。

预览工程与 MP4 成片分别验收。预览通过不代表编码后的画质、声音与同步已经合格；导出后必须检查实际文件。完整评分与返工规则见 [审查规范](references/review.md)。

## 开发与贡献

后续开发围绕四个方向展开：

- 按运行契约实现 Player，并验证任意帧定位、资源就绪和音频试听。
- 实现 Playwright + FFmpeg 渲染链路，验证视频取帧、预览一致性与实际成片同步。
- 增加可运行、可自由改造的参考模板，附来源、依赖和验证说明。
- 增加独立 style 包，提供清晰的视觉描述及必要参考资源。

修改前阅读对应的 [模板约定](references/template-conventions.md)、[Style 约定](references/style-conventions.md)、[品牌素材约定](references/brand-kit.md) 或 [运行契约](references/runtime-contract.md)。涉及 Agent 行为时同步更新 `SKILL.md` 与相关流程文档；涉及接口语义时同步更新调用方和验证方式。

提交变更时，说明解决的问题、变更范围及验证结果。模板和素材需记录来源与使用条件；运行功能需附可复现的检查步骤。不要将尚未执行的动态检查、听音检查或成片验收写成已通过。
