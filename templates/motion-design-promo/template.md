# Motion Design Promo — 20 秒参考模板

本模板是可自由改造的 React 参考工程：动感文字 → 产品群像 → 案例卡片 → 受众 → 搜索行动 → 品牌落版。适合创意工具、设计服务、作品集、精选商品与案例驱动的短发布片。需要解释复杂操作步骤的产品，应把案例段改成真实页面或录屏，而不是用商品/人物拼贴代替功能证据。

## 基准与运行边界

- 六场景与十四段内部动作，整体时长为 20 秒。
- 1280×720，60 fps，1200 帧，20 秒；内部 CSS 舞台保持 1920×1080，再缩放到输出尺寸。原构图以 960×540 逻辑坐标及 cqw/cqh 表达，默认只支持 16:9。
- Runtime 0.1.0 快照随包附带，可独立运行。Node 24+、FFmpeg/ffprobe、锁定版本 Chromium 是外部运行环境。
- 全局帧时间为 `frame/60`，场景半开区间 `[start,end)`。为了保留原导出取样，传给 board 的视觉时间为 `(localFrame+0.5)/60`；音乐保持从 0 开始。这是显式视觉采样偏移，不是额外播放时钟。
- 保留原五次缓动、字体度量、卡片路径、透视、分段权重和场景硬切。JSX 中仅文字字体选择增加按字重区分的字体族；TSX 入口负责 runtime 接线。没有重写动画或新增 SFX。

## 场景与动作

| 时间 / 全局帧 | 场景与内部动作 | 空间与节奏 | 源码 |
| --- | --- | --- | --- |
| 0–3.75s / 0–225 | Intro01：Idea01 0–45；Transform02 45–120；Outcome03 120–180；Bridge04 180–225 | 大字缩放落定与拖影；逐字出现后缩小；结果词扩成三行；连接词缩退 | `src/boards/Intro01.jsx` |
| 3.75–6s / 225–360 | Portfolio02 / Portfolio05 | 商品从外围推入、缩放归位，承诺文字缩小消退，短词落定；保留六张商品的自适应布局 | `src/boards/Portfolio02.jsx` |
| 6–9.25s / 360–555 | Showcase03：Value06 360–420；Showcase07 420–555 | 价值字卡后卡片从下方带旋转和透视交叠飞入；最后一张成为主角，其余消退 | `src/boards/Showcase03.jsx` |
| 9.25–13.25s / 555–795 | Audience04：Explain08 555–675；Audience09 675–795 | 大幅文字运动承接至六个人物/案例的群像入场，形成传播与受众语义 | `src/boards/Audience04.jsx` |
| 13.25–18s / 795–1080 | Conversion05：Invite10 795–825；Action11 825–855；Search12 855–1005；Book13 1005–1080 | 两段短重音字卡；搜索框从放大偏移状态收回，查询文字揭示，光标移向按钮并点击；CTA 落定 | `src/boards/Conversion05.jsx` |
| 18–20s / 1080–1200 | Brand06 / Brand14 | 品牌图形缩放收束并停留，背景回到白色 | `src/boards/Brand06.jsx` |

场景区间在 `src/content.json`，动作锚点在 `film.tsx` 的 markers，内部时长比例在各 board 的 `Sequence.parts`。改变外层时长会同比缩放该场景内部所有动作。当前配乐是既有 120 BPM 纯音乐母带，直接使用完整 20 秒音源；没有旁白或 TTS，也不叠加各场景 MP3，以免引入编码延迟和接缝。

## 素材与首批采集

| 段落 | 数量与格式 | 建议清晰度 / 画面职责 |
| --- | --- | --- |
| 开场 | 4 段短文案 | 单行排版，长句先检查压缩后可读性；不允许默默回退成原产品宣称 |
| 商品群像 | art1–art6 必填，art7–art9 可选；PNG/JPG | 优先 ≥1024px 方图；入场放大约 2.35 倍并有外围位移，不能只按最终小卡尺寸采集 |
| 案例展示 | project1–project3 必填，project4–project5 可选 | 横向约 1.6:1，建议 ≥1600×1000；原 720p 最终主卡约 816×509px；最后一个有效槽位成为主卡 |
| 受众群像 | 6 个图片槽位 | 建议 ≥1024px 方图；可换成客户类型、团队或用例，不能把虚构人物当真实客户证言 |
| 转化 | invitation/action/query/cta 文案 | 搜索框是通用概念组件；若表达真实产品操作，应换真实证据并调整点击位置 |
| 收尾 | 1 张透明品牌 PNG | 建议 ≥1024px，保证放大时清晰；核对透明边距与视觉中心 |

示例实际使用 **18 个槽位、16 张独立图片**：6 商品、5 案例槽位（3 张图片复用）、6 人物、1 Logo。最大支持 21 槽位。示例 SHIQU 是虚构购物平台；商品、页面、人物和 Logo 均须按目标产品替换。首先采集能证明产品输入→操作→输出的真实素材，再决定是否保留每段。

## 换产品的编辑入口

1. 将整个模板复制到 `films/<project-id>/`（不要复制 node_modules、.lvm），在副本修改。
2. `src/content.json` 是当前实际内容接口：`data` 改文字，`media` 把槽位映射至 image id，`images` 把 id 映射到工程内路径。复制素材到 assets，不引用其他工程或远程 URL。
3. 各 board JSON 保存字段语义和长度提示。`translate_only` 在此 skill 中不是强制策略；Agent 可根据产品证据改写全部文案。它们不驱动 runtime；运行内容以 content.json 为准。
4. 必须替换 SHIQU、示例商品/人物、网页与品牌图。可以删减、重排或只取连续段落，但要同时更新 start/end、总帧数、markers 与音频事件。不要把时间线改成 JSON 里原参考的 example_duration_ms。
5. 场景布局在各 board 的局部函数，卡片空间参数在 `src/design.js`。保留已选段落动作关系，不要仅借配色后另造一套模板。长中文、宽 Logo、不同截图比例要逐帧看揭示、缩放、裁切、最终停留。
6. 图片通过 AssetImage 接入，可沿用原 cloneElement 样式覆盖。换视频时用 runtime VideoFrame 显式映射源时间并声明越界策略，源声音另列音频事件，不能插入自动播放 video。

## 颜色、字体与质感

- 白色舞台用于开场与落版；粉→紫文字渐变用于概念词；柔和多色空间场用于商品、案例、受众与转化高潮。网格保持低透明度，阴影/辉光只辅助主体。
- `Design.palette.pink/purple` 控制文字和部分控件；`palette.fields` 是原有采样色场，**不会**自动随 pink/purple 变色。改 style 时分别处理字段、渐变与阴影，保留多色段落的作用，不全片套单一主题色。
- 真实产品截图、人物、商品不参与全局染色。主题色可用于点缀，品牌明确要求优先。
- `Design.metrics` 是 Inter 与中文 fallback 的字形测量数据；SVG 的完整字符串 viewBox 保持不变以避免逐字揭示跳动。换字体必须重建对应 metrics 或改造并验证文字布局，不能只换 CSS font-family。
- 字体八个文件在 `assets/fonts`。runtime 0.1.0 无 FontFace 字重描述，`src/fonts.json` 为 400/800 注册独立别名，Type 以 weight=400、fontSynthesis=none 使用正确物理字体；文本语义字重仍决定 metrics 和字体别名。
- 背景 Mesh 是纯函数生成的 SVG data URL；`useFrameTask` 显式等待解码。此等待参与同一帧握手，不使用固定延时。

## 验证与已知边界

安装和命令见 [README](README.md)，本次证据见 [runtime 验证记录](records/runtime-validation.md)。`npm run validate -- --full` 逐帧覆盖全部 1200 帧，检查十四动作切换以及倒退/重复取帧。默认短检查覆盖每段起止及中间帧。测试缓存仅在 `.lvm/validation`。

画面包含有意的超大字与边缘裁切，改编时不能擅自把它们改成静态全字居中。

资源加载、完整逐帧、声音技术同步与运行可移植性验证不等于新产品商用审美验收；换产品仍需真实动态、听感及独立评测。未要求导出时不生成 MP4。
