# Google Vids — 从一个想法到一支成片（86.72s）

这支片子用“一次完整的创作过程”介绍产品：点击新建、输入需求、引用资料、生成结构、选择视觉、完善内容、团队协作、补充素材、录制讲解，最后播放并揭示品牌。适合有明确输入、处理过程和可展示结果的创作工具、AI 产品与工作流软件。

最值得借鉴的是**同一个对象怎样串起下一镜**：按钮变成入口，输入框拉远露出工作空间，散卡落成图库，图库中的图片放大后又落入编辑器，播放按钮把操作过程送入发布收尾。不是将功能截图依次放进同一个面板。

- 工程规格：1920×1080，30000/1001 fps，2599 帧，约 86.72s。
- 实现：React / TypeScript / SVG，统一帧驱动；[film.tsx](film.tsx) 是影片入口。
- 借用方式：可选择连续段落、增删功能、重排叙事；保留所选段落的动作、镜头、空间关系、构图和节奏，再适配产品内容与 style。
- 原片与复刻：下文视觉观察来自用户提供的原片，章节边界与修改入口来自当前 React 工程。代码在光标、相机、模糊及部分切点上有近似；贴近参考时以原片为准，不把代码近似作为新的设计标准。

## 一、先看懂整支片子

**节奏骨架**：极简入口与角色词 → 点击加速、巨字输入 → 拉远展示输入与生成 → 大小视野切换展示多种结果 → 文案/声音/协作的连续操作 → 图库铺满、选中主角并落入真实工作空间 → 人物录制提供使用情境 → 播放脉冲、快速用途字卡 → 品牌安静落定。

大字、局部 UI 特写、全景、密集内容墙和人物镜头交替出现。留白承担阅读与蓄力，局部高饱和色和大尺度运动承担强调；并非整片维持一种背景、一种尺寸或一种颜色。

[查看原片关键帧对照图](docs/reference-contact-sheet.jpg)：包含按钮、三角转场、输入、分镜、散卡、作品图库、不同作品配色、声音图形、协作、素材墙、人物与收尾。图中时间来自原视频，仅用于理解参考，不作为影片场景贴图。

## 二、逐段动作、空间调度与改造重点

以下秒数用于定位当前源码中的子段落，原片动作可能略有错位。对照时同时看起势、峰值、收势与下一镜承接，不只比较落定截图。

### 1. 入口 → 菜单 → 巨字输入（0–9.4s）

- 开场三组对象横向排布：深灰固定句、浅色 New 按钮、渐变角色词。角色词轮换；两侧文字退场，按钮长成主角，手形指针靠近、按下、释放。
- 菜单出现后发生纵向位移，指针命中 Vids 行；背景菜单变虚，三角播放形从小到大、前后错位地掠过。三角形的紫/洋红逐步过渡到蓝/青，承担动作的方向与能量。
- 三角带让位于超大输入文字。文字不是一开始就完整落在小输入框里，而是边输入边改变尺度和取景；语义重点使用渐变，辅助词保持深灰。
- 换产品：保留“入口成为主角 → 点击引发下一镜”的因果。替换入口、角色词和具体任务；重算输入分段、光标位置、字宽和取景。不要只替换最终字符串而保留旧词的打字切片与位移。

### 2. 需求 → 文件 → 大纲（9.4–17.8s）

- 输入视野拉远，前景的大文件图标与后景的小图标形成纵深；一份文件被选中，收进输入区成为附件，随后触发生成。
- 约 13.2–14.75s 的 Creating 是高彩度胶囊的推近与转向，不是静止的加载文字。它把等待压缩成一段动作，再交给大纲。
- 大纲从局部、带透视的行列变成可读全景，结尾指针点击 Next。模板含 8 行；每行的长度、图标和间距都参与镜头尺度。
- 换产品：文件类型必须是目标产品实际接受的类型；任务、附件内容、大纲结果要对应同一个案例。改行数时同步改面板高度、行位置、相机取景和点击目标。

### 3. 标题 → 散卡 → 图库 → 大图（17.8–26.95s）

- 大标题缩回可读尺度，前缀离开，留下可点击的 style。点击后，卡片从画面四周与前后景聚拢，存在遮挡、旋转与大小差，不是 12 张等大卡片一起淡入。
- 图库落定为 4 列×3 行，界面保持浅色；卡片内容各自有黄、粉、紫、深绿、青、白等配色，证明“有多种结果可选”。
- 约 24.25s 起连续切换三张大作品：黄底深字与圆角几何、粉底与橙色星形、薄荷底与深青色块。它们是**作品内容的不同设计**，不是把产品主题色调成三个深浅。
- 换产品：优先用官网 good cases 或实际生成结果，选择题材与配色有差异的真实素材。缩略图与放大展示的结果应对应；为会靠近镜头的卡片准备单独高清源，不能把小缩略图硬放大。

### 4. 文案 → 声音（26.95–46.2s）

- “write my script”从大字收成操作提示，麦克风按钮承接点击；脚本文字在面板中生成，再推到几乎充满画面的局部。
- 声音标题再次使用巨字与横移，引出不同大小的椭圆、圆形、胶囊。粉、紫、青、蓝、黄的渐变形体表达声音的多样性与流动，不是背景装饰。
- 声音列表有不同颜色的识别圆点；镜头推近一个选项，指针点击，再进入播放反馈。保留“看到选择 → 发生选择 → 看到结果”的顺序。
- 换产品：脚本必须属于前面那个案例；当前代码的打字计数、巨字位移是手写时间锚点，换长度需重调。没有配音能力不能借 Voice 列表伪装其他功能。无声影片可以展示有依据的声音功能，但不能把画面中的波形或播放动画当作真实试听证据。

### 5. 评论 → 协作画布 → 评论流（46.2–53.35s）

- 一张大评论卡先提供具体问题，再切到共同操作的作品；不同颜色的协作者光标/姓名标识帮助区分人物。
- 作品中的照片、深青色版式、浅色 UI、蓝色选区各有归属。随后评论卡上下流动，通过尺度、位置和透明度区分当前信息与前后信息。
- 换产品：准备一个真实可演示的协作场景；头像、名字、评论与选中对象要互相对应。没有授权的真实用户信息不能直接搬用；演示数据注明用途，不包装成客户背书。

### 6. 搜索 → 照片墙 → 编辑器（53.35–64.3s）

- 工具按钮点击后出现素材面板，搜索输入被放大；镜头退出输入特写，照片以不同宽高组成铺满画面的内容墙。
- 选中的拱门照片从墙中脱离、放大，其余素材退去；同一张图再缩进编辑器中的目标位置。重点是**同一对象的连续空间路径**，不是图库与编辑器之间硬切。
- 编辑器全景展示画布、工具栏、时间线与播放控件；时间线横移让人知道结果是一段可编辑的视频。
- 换产品：保持真实照片/案例原色。准备同一素材的列表态与高清态，以及目标画布位置；用真实界面截图/录屏支撑功能。不要沿用 Google 菜单与时间线，仅贴上新 Logo 充当目标产品。

### 7. 录制 → 人物 → 作品（64.3–75.8s）

- 由编辑器工具栏进入录制，浅色空间切到黑色录制控件，红色按钮表示录制状态。
- 巨大倒计时数字向镜头穿过，后方人物失焦；录制开始后人物清晰可见。
- 人物从录制空间进入作品分区，与文字、图片共同组成内容；再回编辑器，镜头推向 Play，完成操作链。
- 换产品：使用目标产品允许展示的人物片段，保证前后人物、口型、画面内容连贯。删录制段时重新设计从编辑结果到 Play 的承接，不能留下失去来源的人物窗口。

### 8. Play → 用途快切 → 品牌落定（75.8–86.72s）

- 浅色 Play 胶囊被点击，局部波纹扩大，转到“AI powered / video creation app / for work”等短句；重点词渐变，其余文字深灰。
- 用途字卡先在浅底上出现，随后进入高饱和蓝/青舞台、白字快切，形成收尾峰值，再退回白底 Logo。**大面积高饱和色在这里是阶段性的节奏变化**。
- Google Vids、coming soon、应用图标、Workspace 是原产品发布信息。换产品时分别判断是否保留对应叙事，不默认目标产品也有生态集成或待发布状态。
- 结尾给新产品名称、定位或 CTA 留下完整阅读时间；短词快切节奏不能原样套给一长串中文用途。

## 四、颜色按用途分工，不做全局换主题色

先区分“舞台/界面”“产品身份”“作品内容”“动作强调”再应用 style。下面的颜色名是设计职责，不是已经存在的配置接口；当前源码没有一个可以替换所有颜色的 `brandColor` 开关。

| 颜色职责 | 原片中的具体表现 | 换产品与 style 的方式 |
| --- | --- | --- |
| 阅读舞台 | 大部分时间为白/近白底、深灰文字；少量青/紫柔光提供空间感 | 保持文字层级与留白；按 style 调整底色和墨色，不把整片染成产品色 |
| 控件表面 | New / Play 是低饱和浅蓝表面、轻微渐变边缘、柔影；图标文字仍深色 | 与高彩度按钮区别处理；保留按压反馈、边缘和明暗层次，不能只填一个纯品牌色 |
| 语义强调 | 角色词、输入任务的重点、AI / work 用青—蓝—紫渐变 | 渐变承担局部强调，可以按 style 选协调色谱；不需要只来自 Logo 色，也不把整句都做渐变 |
| 动作与转场 | 三角带的紫/洋红→蓝/青；Creating 胶囊；声音彩色形体 | 保留多色变化、前后层次和饱和度的起落；可以改色谱，不能因“品牌色只是点缀”就全部去色 |
| 功能与状态 | 文件类型图标的蓝/绿/黄/紫、选中态蓝色、协作者不同标识、录制红色 | 保留识别与状态语义，按真实目标 UI 处理；第三方 Logo 不统一染成目标品牌色 |
| 作品自身的色彩 | 图库多种设计；大图黄/粉/薄荷切换；深青色太阳能案例；摄影的自然色 | 这是产品展示的内容，不是宣传片外壳。真实截图、案例和照片保持原色；不能为了统一风格重绘成一套同色假案例 |
| 阶段性满屏色 | 用途快切段突然进入高饱和蓝/青与白字，再回白底落版 | 可以按 style 改为另一组高能配色，但保留这一段与前后段的对比。品牌色是否参与由局部作用决定，不由面积配额决定 |
| 品牌身份 | Logo、产品名、Google 多色字标与生态图标 | 替换为目标产品有依据的身份元素；不把参考品牌的多色标志挪作目标品牌资产 |

例如：绿色 Logo 的产品仍可在浅色舞台上展示黄/粉/蓝的真实作品，以青紫转场连接镜头，并只在少数主操作或品牌落点用绿。也可以按所选 style 调整转场色谱。判断标准是**颜色是否说明内容、状态与动作，是否保留参考的层次**，不是“每个元素都能找到同一主题色”。

## 五、换产品指南

### 1. 先确定产品与案例，再选段落

阅读官网、源码或可用产品，整理用途、受众、卖点、必展功能和执行限制；同时采集真实页面与 good cases。为章节表逐项标注“保留 / 用真实功能改造 / 删除”及证据。优先串起一个可理解的端到端案例，不拼接互不相关的示例输入与结果。

### 2. 建立独立影片工程

将所需源码、资源、`package.json`、锁文件和 `vendor/` 复制到仓库 `films/<project-id>/`，该目录被 Git 忽略。排除 `node_modules/`、`.lvm/`、旧导出与旧评测报告；不让新片运行时引用模板路径。记录参考版本与借用时间段。新片不继承模板的评分或验收状态。

### 3. 把镜头与素材逐一对应

在分镜里记录“原片段落 → 本片段落 → 产品事实 → 资源文件 → 动作/取景 → 改造原因”。先补齐将成为镜头主角的高清素材，再写动画：特别是散卡前景、三张放大结果、图库主角与真实编辑界面。素材准备好后才锁定卡片数量、槽位、点击坐标与相机终点。

### 4. 按源码入口替换内容，保留运动关系

| 修改入口 | 必须检查的替换项 | 需要一起适配的动作 |
| --- | --- | --- |
| `Opening` / `Prompt` | 角色词、入口/菜单、任务文案 | 按钮与侧词间距，打字片段、光标 x、横向取景、三角带接缝 |
| `Generate` | 文件种类/名称、附件、大纲行 | 文件落位、行数/高度、透视与全景边界、Next 点击 |
| `StyleScene` | 图库资源、三张大图、作品标题和标志 | 卡片的前后层次、4×3 槽位、放大对象连续性、3 张切换节奏 |
| `ScriptVoice` / `Collaborate` | 脚本、选项标签、头像/姓名/评论、作品 | 打字终点、长文推近、选中位置、评论流可读时间与遮挡 |
| `MediaScene` / `Editor` | 搜索词、素材列表、主角图、真实产品界面/项目名/时间线 | 墙内图的位置 → 前景 → 画布槽位；点击必须命中真实控件 |
| `RecordScene` | 人物资源、录制状态、作品分区 | 倒计时、视频取帧、人物裁切、回编辑器与 Play 的连续性 |
| `Finale` | 定位、用途、品牌、发布状态/CTA、生态标识 | 逐词时长、色彩峰值、Logo 落定与阅读时间 |

当前文案和颜色分布在各组件内，不能只改 `film.tsx`。`StyleCard` 和 `Editor` 中还有太阳能案例文字及示例品牌；结束后全文搜索旧产品名、文件名、人物名、案例词与 Logo 引用，逐项决定替换或删除。源码重绘 UI 可以用于镜头适配，但必须以真实功能和布局为依据；概念示意不能冒充实际截图。

### 5. 按颜色职责融合 style

先保持参考的空间与时序，再按上一节分别处理底色、正文、渐变、控件、状态和品牌落点。真实案例原色不动。换字体后逐镜检查最大字号、字宽、换行与光标，不用压成小字或通用标题面板来回避原镜头的巨字构图。

### 6. 改时长时更新所有时间锚点

当前每个组件收到的是**全片绝对帧**；`sec(frame)` 得到全片秒数。只改章节表不会自动平移组件内的动作。

- `film.tsx`：同时更新 `chapters`、`Frame` 的分支边界、总帧数与 `markers`。
- 场景内：调整所有 `t` 阈值、`tr` / `p` 的秒数锚点，以及 Opening / Prompt 中的绝对帧键。成组平移同一段的动作，核对入场与出场重叠。
- 媒体：更新人物片段的取帧起点、裁切与 `outOfRange` 处理，不能让旧的 hold 掩盖素材不足。
- 资源：同步 `src/media.ts`、`film.assets` 与实际引用，删段也移除无用声明，避免仍要求准备不会出镜的资源。
- 声音：若使用声音，同步 `film.audio` 的位置、源片段、裁切、音量和淡入淡出；不直接拉伸原混音套在改过的镜头上。静音任务使用空声音时间线并移除原参考音轨资源。

可在派生工程中把段落改为局部帧以方便重排，但要完整转换该段所有动画与媒体锚点，并按运行契约验证；不能只改函数参数就宣称完成重定时。

### 7. 逐镜检查后再交付

每段至少检查起势、动作峰值、落定和下一段接缝，并连续播放观察；散卡、巨字、图片入画布及人物切换加密取帧。完成内部修复后，按 [独立评测要求](../../references/review.md) 评测当前版本。默认交付可预览工程；用户要求时打开预览，明确要求导出后才生成 MP4。

## 六、共用实现与检查重点

| 入口 | 作用与约束 |
| --- | --- |
| [film.tsx](film.tsx) | 规格、章节元数据、资源、音轨、动作标记与画面路由；章节表和路由是两处，需要一起维护 |
| [ui.tsx](src/ui.tsx) | 浅色舞台、面板、渐变文字、文件图标、照片、播放控件、标题等；共享颜色不是全片唯一调色入口 |
| [motion.ts](src/motion.ts) | 帧/秒进度与插值工具；缓动决定动势，替换素材时不要顺手重置所有曲线 |
| [Icons.tsx](src/Icons.tsx) | 手形指针等 SVG；点击位置、按压与对象反馈需匹配 |
| [media.ts](src/media.ts) | 图片 ID 清单；改名或删资源同步声明与引用 |
| [media-provenance.json](records/media-provenance.json) | 原片取样时间、裁切与已知媒体限制，用于识别哪些只是参考素材 |

验收时尤其关注：

- **结构可认**：保留参考的近远景、对象接力、空间调度和节奏；不能只保留一句文案或一套缓动函数就称“复刻”。
- **产品可信**：能看见具体用途、真实输入/结果与关键功能；没有假案例、假按钮、残留原品牌或未经证实的功能暗示。
- **颜色有分工**：浅 UI、语义渐变、内容色彩、状态色与满屏峰值各在合适位置；既非全品牌色，也非全灰色。
- **移动中也清晰**：主角卡放大时不糊；巨字不意外截断；必要文字有阅读停留；真实截图不套统一滤镜。
- **操作有因果**：指针落在点击目标，按下/释放有反馈；素材飞入正确槽位；分镜变化不使对象突然消失或跳位。
- **连续性与技术**：边界帧无闪黑/漏层，乱序取帧一致，资源全部就绪；人物视频不是用不合理停帧蒙混过去。有声音时另查音画同步。

## 七、运行与来源

需要 Node.js 24+、FFmpeg/ffprobe 和 Playwright Chromium。包内锁定 runtime；首次使用在本目录执行：

```sh
npm ci --ignore-scripts
npm run setup
npm run prepare
# 指定帧内部检查，不导出影片；目标文件须尚不存在
npm run still -- 704 /tmp/google-vids-frame-704.png
# 用户请求时打开预览
npm run preview -- --open
# 用户明确要求导出后执行
npm run render -- exports/film.mp4
```

更改源码或资源后重新 prepare 并启动预览，避免用旧 content version 观看。安装与预览细节遵循 [运行契约](../../references/runtime-contract.md)。`.lvm/`、`node_modules/`、`exports/` 是本地生成内容。

本模板是用户提供的 *Introducing Google Vids* 的研究性 React 复刻。原片来源见 [brief.md](records/brief.md)，媒体裁切见 [media-provenance.json](records/media-provenance.json)，文档对照图见 [来源说明](docs/README.md)。原始完整 MP4 不包含在包内，本机来源路径只用于溯源，不是运行依赖。参考混音包含原片声音，不能当成新产品影片的可用 BGM 或音效授权。

“源码能运行”和“成片达到质量标准”分别验证。当前实现与原片仍有差异，例如部分标题缩放与转场时序、声音反馈的色彩、收尾用途文字、光标与图标细节；太阳能 poster 含原片指针，最后编辑器内的小人物片段存在 hold。新片应按实际素材和原片观察修正，不继承这些近似，也不能继承任何旧评分。
