# Capsule Flow — 从一个想法到一支成片（82.05s）

这支片子用“一次完整的创作过程”介绍产品：点击入口、输入需求、引用资料、生成结构、选择视觉、完善内容、展示结果，最后揭示品牌。适合有明确输入、处理过程和可展示结果的创作工具、AI 产品与工作流软件。**TapVid 只是随包的可运行示例，不是模板的名称或适用边界。**

最值得借鉴的是**同一个对象怎样串起下一镜**：类型胶囊变成入口，巨字输入拉远露出完整胶囊，胶囊展开成输入界面，散卡落成图库，创建符号带出结果，磨砂品牌按钮送入发布收尾。不是将功能截图依次放进同一个面板。

- 规格：1920×1080，30000/1001 fps，2459 帧，约82.05s。
- 实现：React / TypeScript / SVG，统一帧驱动；[film.tsx](film.tsx) 是入口。
- 借用方式：默认保留动作、镜头、空间关系、构图和节奏，只适配产品内容与 style。删改应以产品事实、用户要求或规格为依据，遵循[模板适配约定](../../references/template-conventions.md)。
- 参考边界：基于 Google Vids 的叙事与镜头组织，加入立方类型翻转、胶囊展开、创建符号转场和磨砂按钮；删去三个独立成果特写、声波与倒计时。下文描述当前模板，不把近似代码当作原片事实。
- 产品名、URL、绿色配色、手指Logo、飞机符号、截图、案例与文案都是示例内容。目标产品无需使用相同品牌色、图标或功能名称。

## 一、先看懂整支片子

**节奏骨架**：极简入口与类型词 → 点击加速、巨字输入 → 拉远并展开输入界面 → 生成结构 → 散卡聚拢为成果墙 → 内容完善与品牌表达 → 灵感与编辑 → 创建转场与结果播放 → 用途快切 → 品牌安静落定。

大字、局部UI特写、全景、密集内容墙和真实结果交替出现。留白承担阅读与蓄力，大尺度运动承担强调，高饱和舞台形成阶段性峰值。

## 二、逐段动作、空间调度与改造重点

对照起势、峰值、收势与下一镜承接，不只比较落定截图。

### 1. 入口 → 菜单 → 巨字输入

- 固定句与类型胶囊横向排布；中间词立方翻转，周边细线跑动。两侧文字退去，胶囊成为入口，指针按下、释放。
- 菜单纵向移动后命中目标，创建图形由小变大并错位掠过，再让位于超大任务输入。语义重点渐变，辅助词保持深灰。
- 换产品：替换类型、入口、菜单和任务，同步重算字宽、打字切片、光标与取景。图形可换成目标产品创建符号，保留从控件到转场的形状联系。

### 2. 需求 → 输入界面 → 结构

- 沿用上一镜末帧，先从文字特写拉回完整胶囊，再连续改变同一外壳的高度、圆角和表面。不能直接切到另一张UI。
- 资料标签落到正文上方，底部参数和创建控件显现，点击后进入Creating推转，再拉至结构全景。
- 换产品：URL只是当前示例，可换实际支持的文件或其他输入。输入、提示词和结构要对应同一案例；改变内容后重算控件、点击和阅读时长。

### 3. 标题 → 散卡 → 图库

- 巨字收拢，入口点击；卡片从四周和前后景聚拢，保留旋转、大小与遮挡差异，落成4×3网格。
- 当前版本图库后直接进入内容完善，无底部播放栏及三个独立放大镜头。
- 换产品：使用题材和配色不同的真实成果；数量变化要同步网格和轨迹，靠近镜头的卡片必须使用高清源。

### 4. 内容 → 品牌表达

- 大字收成操作提示，内容面板生成并推到局部；形态变化与真实设置界面接力，表达内容可塑性。
- 口号段保持清楚文字和舞台，不使用声波。ScriptVoice是遗留文件名，不要求目标产品具备声音功能。
- 换产品：展示真实生成、设置或规范能力，缺乏对应功能就改造叙事，不借示例界面作虚假宣称。

### 5. 修改 → 编辑结果

- 明确的修改请求引出真实界面，通过近景与全景展示修改发生的位置。
- 换产品：准备同一案例的前后状态，确保文字请求与变化对应；源码重绘UI需以真实功能和布局为依据。

### 6. 内容墙 → 灵感与细化

- 多尺寸内容铺开，主角素材和细化界面接力；保持对象身份、比例及空间路径。
- 换产品：墙内素材与靠近镜头的主角分开准备清晰度，真实内容保持原色。

### 7. 创建 → 结果

- 深色控件中的创建符号被强调，同形符号带出结果。无录制倒计时，不表示一定发生人物录制。
- 换产品：结果可为设计、仪表板、生成内容或其他真实输出；当前人物视频只是示例。独立案例须明确标注，不能声称由前面演示输入真实生成。

### 8. 品牌按钮 → 用途快切 → 落版

- 大圆角磨砂按钮使用浅色表面、白色高光边和柔影，完整标志居中；点击轻微压缩，波纹带出定位短句。
- 用途先在浅底出现，再进入高能舞台，最后回到Logo和CTA。
- 换产品：替换完整标志、用途和定位，保持原生比例。短词节奏不直接套长句，不继承示例的功能或发布状态。

先建立“卖点 → 证据 → 可用画面 → 对应段落”，研究时采集首批真实内容，不让分镜被假素材填满。

## 四、颜色按用途分工，不做全局换主题色

先区分“舞台/界面”“产品身份”“作品内容”“动作强调”再应用 style。下面的颜色名是设计职责，不是已经存在的配置接口；当前源码没有一个可以替换所有颜色的 `brandColor` 开关。

| 颜色职责 | 当前示例 | 换产品与style |
| --- | --- | --- |
| 阅读舞台 | 白底、深灰文字、低透明绿光 | 保留层级和留白，可改底色墨色 |
| 控件表面 | 浅色入口；磨砂灰绿/灰蓝、白边柔影 | 保留材质与按压，不简单填纯品牌色 |
| 语义强调 | 亮绿→叶绿→亮绿 | 这是示例色谱，可换协调渐变 |
| 动作与转场 | 创建符号带、Creating、形态 | 保留方向、层次与饱和度起落 |
| 功能与状态 | 真实界面的状态色 | 尊重目标产品UI语义，不全局染色 |
| 作品内容 | 多色案例与真实结果 | 保持原色，避免同色假案例 |
| 满屏峰值 | 用途快切高饱和舞台 | 按style调色，保留阶段性节奏变化 |
| 品牌身份 | 示例Logo与产品名 | 替换为目标品牌有依据的元素 |

src/palette.ts集中示例渐变，但不是全片唯一调色入口。磨砂材质、功能状态和真实内容有独立职责。模板不要求绿色，也不要求使用飞机或手指品牌形象。

## 五、换产品指南

### 1. 先确定产品与案例，再选段落

阅读官网、源码或可用产品，整理用途、受众、卖点、必展功能和执行限制；同时采集真实页面与 good cases。为章节表逐项标注“保留 / 用真实功能改造 / 删除”及证据。优先串起一个可理解的端到端案例，不拼接互不相关的示例输入与结果。

### 2. 建立独立影片工程

将所需源码、资源、`package.json`、锁文件和 `vendor/` 复制到仓库 `films/<project-id>/`，该目录被 Git 忽略。排除 `node_modules/`、`.lvm/`、旧导出与旧评测报告；不让新片运行时引用模板路径。记录参考版本与借用时间段。新片不继承模板的评分或验收状态。

### 3. 把镜头与素材逐一对应

在分镜里记录“原片段落 → 本片段落 → 产品事实 → 资源文件 → 动作/取景 → 改造原因”。先补齐将成为镜头主角的高清素材，再写动画：特别是散卡前景、图库主角与真实编辑界面。素材准备好后才锁定卡片数量、槽位、点击坐标与相机终点。

### 4. 按源码入口替换内容，保留运动关系

| 修改入口 | 替换项 | 联动检查 |
| --- | --- | --- |
| Opening / Prompt | 类型、入口、菜单、任务 | 立方背面、标签交接、打字、光标、取景 |
| Generate | URL/附件、参数、提示词、提纲 | 胶囊尺寸、圆角、中心连续；资料落位与点击 |
| StyleScene | 标题、入口、图库 | 散卡层次、网格、出场接缝 |
| ScriptVoice / Workflow | 脚本、品牌、修改、案例、结果 | 文案对应、截图裁切、点击与视频取帧 |
| Finale | 标志、定位、用途、CTA | 原生比例、材质、按压与阅读停留 |
| palette / CreatePlane | 渐变、创建图形 | 跨镜同形，真实内容原色 |

没有统一配置面板；文案分布在组件中。完成后搜索TapVid、tapvid.ai、旧任务、案例与Logo引用，逐项替换或说明，不能只改film.tsx。

### 5. 按颜色职责融合 style

先保持参考的空间与时序，再按上一节分别处理底色、正文、渐变、控件、状态和品牌落点。真实案例原色不动。换字体后逐镜检查最大字号、字宽、换行与光标，不用压成小字或通用标题面板来回避原镜头的巨字构图。

### 6. 改时长时更新所有时间锚点

film.tsx接收输出帧，通过toSourceFrame映射后传入组件。当前删去源帧[727,808)及[2005,2064)，内部动作仍使用源时间。

- 修改src/timeline.ts时同步检查总帧数、章节、路由与markers。
- 改内部时成组调整t/tr/p与绝对帧锚点，不只改章节表。
- 更新媒体取帧、裁切、hold和资源声明。
- 更新音轨结束、裁切、增益与淡入淡出；静音任务使用空音轨。
- 转换局部帧须覆盖整段动作及媒体，随后验证任意帧一致性。

### 7. 逐镜检查后再交付

每段至少检查起势、动作峰值、落定和下一段接缝，并连续播放观察；散卡、巨字、图片入画布及人物切换加密取帧。完成内部修复后，按 [独立评测要求](../../references/tech.md#质量保证) 评测当前版本。默认交付可预览工程；用户要求时打开预览，明确要求导出后才生成 MP4。
## 六、共用实现与检查重点

| 入口 | 作用 |
| --- | --- |
| film.tsx | 规格、资源、音轨、章节、路由与markers |
| src/timeline.ts | 源帧/输出帧映射、删段与总长度 |
| src/ui.tsx / motion.ts | 舞台、面板、标题、插值与缓动 |
| src/palette.ts | 示例渐变与柔光 |
| src/CreatePlane.tsx / Icons.tsx | 示例创建符号和指针 |

重点帧：281/282前镜连续；305/306胶囊形变；727图库切点；1924结果接缝；2133–2191磨砂按钮；2458末帧。立方不能露倒字，标签不能重影。任意帧检查不代替连续动态与声音验收。

验收时尤其关注：

- **结构可认**：保留参考的近远景、对象接力、空间调度和节奏；不能只保留一句文案或一套缓动函数就称“复刻”。
- **产品可信**：能看见具体用途、真实输入/结果与关键功能；没有假案例、假按钮、残留原品牌或未经证实的功能暗示。
- **颜色有分工**：浅 UI、语义渐变、内容色彩、状态色与满屏峰值各在合适位置；既非全品牌色，也非全灰色。
- **移动中也清晰**：主角卡放大时不糊；巨字不意外截断；必要文字有阅读停留；真实截图不套统一滤镜。
- **操作有因果**：指针落在点击目标，按下/释放有反馈；素材飞入正确槽位；分镜变化不使对象突然消失或跳位。
- **连续性与技术**：边界帧无闪黑/漏层，乱序取帧一致，资源全部就绪；人物视频不是用不合理停帧蒙混过去。有声音时另查音画同步。
## 七、运行与来源

需要 Node.js 24+、FFmpeg/ffprobe 和 Playwright Chromium。包内锁定 runtime；首次使用在本目录执行：

```sh
npm ci --ignore-scripts
npm run setup
npm run prepare
# 指定帧内部检查，不导出影片；目标文件须尚不存在
npm run still -- 704 /tmp/capsule-flow-frame-704.png
# 用户请求时打开预览
npm run preview -- --open
# 用户明确要求导出后执行
npm run render -- exports/film.mp4
```

更改源码或资源后重新 prepare 并启动预览，避免用旧 content version 观看。安装与预览细节遵循 [运行契约](../../references/tech.md)。`.lvm/`、`node_modules/`、`exports/` 是本地生成内容。

本模板是Google Vids镜头组织的改写版本，TapVid仅作为可运行示例。素材与参考声音来源见[SOURCES.md](SOURCES.md)，来源历史保留具体产品名以便溯源，不构成适用范围限制。

源码运行与成片质量分别验证。独立安装、准备和抽帧记录见[validation.md](records/validation.md)，包审查见[package-review.md](records/package-review.md)。完整连续动态和主观听感尚未完成，新片不继承任何旧评分。参考BGM与字体不能视为通用商业授权。
